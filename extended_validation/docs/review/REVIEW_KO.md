  18,385개 중 16,081개, 별도 입력은 18,367개 중 16,049개가 보호 범위에 든다.
  후자의 coverage는 87.3795%이다. 보호 범위에서는 판정 반전과 오차 한계 위반이 없다.

## 강점

기존 연구는 “오차가 조금 작다”에서 멈추지 않고 응용의 최종 판정과 연결한다.
실제 Lattigo 실행, 구성 선택과 별도 입력 평가의 분리, 새 키 반복,
보안 파라미터 정책, 실패 원인별 조정, 고정된 평가 상한을 구현했다.
단일 숫자 성공률 대신 적용 범위를 설명하고 1/131의 음성 결과도 보존했다.
논문은 83.43%를 실행시간 감소로 바꾸어 주장하지 않고, 지연시간 신뢰구간이 1을
포함함을 인정한다. 이는 신뢰할 수 있는 출발점이다.

## 심사자가 공격할 핵심 문제

### R1. 제외한 입력이 오히려 문제의 핵심 아닌가?

PDF 3쪽 식 (3), 8쪽 Table 5, 9쪽 5.5절은 경계 영역 제외를 명시한다.
따라서 은폐나 산술 오류가 아니다. 그러나 실제 운영에는 그 입력들도 도착한다.
WDBC 2층 MLP의 한 사례는 별도 입력 113개 중 23개만 평가 대상이다.
평균 coverage만 제시하면 가장 어려운 사례가 가려진다. 현재 결과는
“범위 내 선택 성공”이며 “실환경 전체에서 결정 보존”이 아니다.

DeciProtect 대응: 제외 없이 전체 입력을 분모에 넣고, 반환·재계산·유보를
명시적인 동작으로 정의한다. 평균, 최저 사례, 데이터군별 coverage와
반환된 판정의 오류를 함께 측정한다. 이번 구현과 실험에서 시작했다.

### R2. 평문을 알아야 결정 보존 여부를 검사할 수 있는데, 운영에서는 누가 아는가?

구성 선택 때 평문 마진을 쓰는 것은 가능하다. 운영 중 매번 평문 추론을 실행하고
그것으로 안전 여부를 판단하면 배포 모델과 비용이 달라진다. 모델 소유자, 입력 소유자,
키 소유자, 사전 검증 데이터의 소유자를 구분해야 한다.

대응: 신뢰된 보정 단계와 클라이언트 판정 단계를 분리한다. 클라이언트는 복호화된
logit과 사전 고정 오차 구간만 사용한다. `interval_gate`는 평문 점수를 인자로 받지 않는다.
현재 harness는 두 역할을 한 프로세스 환경에서 측정하므로 분산 배포 검증까지 완료한 것은 아니다.

### R3. 부등식 하나와 오차 기준 변경 외에 무엇이 새로운가?

이진의 |error| < margin과 다중 클래스의 두 오차 합 조건은 표준적인 충분조건이다.
PDF 4.2절도 민감도 추정을 분석적 CKKS 오차 보증으로 부르지 않는다.
기여는 자동 구성과 판정 검증의 결합, 자원 상한 내 탐색, 운영 목표의 정식화에서
증명해야 한다. 더 큰 모델을 추가하는 것만으로는 이 질문을 해결하지 못한다.

대응: 위험·유효 반환율·총비용을 동시에 제약한 문제를 정식화하고,
평문 oracle 없이 수행하는 판정 규칙, 독립 평가 단위에 대한 위험 상한,
배치 비용을 고려하는 선택 정책을 하나의 재현 가능한 시스템으로 검증한다.
선행 selective prediction/위험 제어 자체를 새 발명으로 주장하지 않는다.

### R4. 보수적인 고정 구성이나 오차 기준 탐색보다 좋은가?

83.43%는 537개 유한 후보 전체 평가 대비 절약이다. 후보 집합을 크게 만들면 이 수치는
커질 수 있다. 최소 오차 대조군이 이미 0/68 위반이라는 사실도 함께 다뤄야 한다.
일괄 높은 정밀도, 같은 예산의 순차 탐색, 무작위 탐색, 고정 절대오차 기준,
마진 없는 구성, 기존 컴파일러 + 동일 판정 gate를 비교해야 한다.

대응: 후보 수·키 수·데이터·보안·packing·측정 범위를 맞춘 비용-위험-coverage
Pareto 비교를 사전 정의한다. 새로운 파일럿은 고정 고정밀도와 재계산을 실제로 비교했고,
재계산이 느려지는 음성 결과를 얻었다. 이 결과를 그대로 보존한다.

### R5. 0회 관측으로 미래 입력의 안전성을 말할 수 있나?

세 키 반복과 많은 slot은 독립 표본 수를 세 배로 만들지 않는다. 교차 검증 모델은
학습 자료를 공유하며, 68개 사례도 독립적인 68개 환경이 아니다. 단순 binomial bound를
16,049×3에 적용하는 것은 정당화되지 않는다. 심지어 정말 독립적인 23회가 모두 성공했어도
실패율의 단측 95% 상한은 약 12.2%이다. 이는 설명용 수학 예시이며 기존 WDBC 실행에
통계적 보장을 소급 부여한 것이 아니다.

대응: 고정 모델과 고정 키 조건의 위험, 새 키에 대한 위험, 새 분포에 대한 위험을
분리한다. DP_IID_AUDIT_V1은 입력+새 키를 매번 독립 생성하며, 1,322행으로 명시한
유한 모집단에 대해서만 두 위험 상한을 다중 비교 보정해 평가한다.

### R6. 실제 데이터와 모델이 충분한가?

주요 68개 중 65개는 작은 tabular 모델 계열이고, 큰 다중 클래스 두 모델은 주 평가에서
각각 하나의 학습 모델이다. 전체 작업공간에는 추가 학습 seed, 비표형 영상, 깊이 실험이
이미 있으므로 “CNN이나 독립 seed 실험을 전혀 하지 않았다”는 평가는 틀리다.
부족한 것은 대표성 있는 보안 서비스 데이터, 시간/기관 분할, 충분한 다중 클래스
표본, 모델 품질을 통제한 큰 구조, 독립 장비에서의 정식 비교이다.

대응: 새 스팸 데이터와 두 모델·세 seed를 실행했다. Wine은 작은 표본에서의
유보 실패 대조군으로 남긴다. 다음은 credit-default, Fashion-MNIST,
UNSW-NB15/CIC-IDS2017의 시간·호스트 기반 분할이며 범위와 실행 조건을 미리 정한다.

### R7. 평문 모델의 잘못된 판단도 보존하는 것 아닌가?

맞다. 결정 일치는 정답률, 임상 안전성, 사기 탐지 품질과 동일하지 않다.
원래 모델→다항식 근사 모델의 변경과 다항식 평문→CKKS의 변경을 별도로 기록해야 한다.
단순 square 모델을 쓰면서 원래 ReLU 모델의 판단을 지켰다고 주장하면 안 된다.

대응: 평문 accuracy, balanced accuracy/F1/AUPRC, 모델 변환 전후 일치,
CKKS 일치, 유보를 실패로 포함한 최종 효용을 분리한다. 이번 파일럿은
평문 accuracy와 CKKS 일치·반환율을 분리했고, 모델 변환 보장은 주장하지 않는다.

### R8. 보안 및 회전·부트스트래핑 범위는 어디까지인가?

Q/QP 표 적합성은 가정하의 파라미터 admission이다. 분석 도구가 존재한다는 사실과
모든 현재 구성의 exact 보안 추정이 완료됐다는 사실도 다르다.
판정 일치는 악의적인 서버의 계산 변조를 검출하는 검증 가능 계산이 아니다.
키 재사용, 복호화 결과 노출, 재계산 요청이 전달하는 정보도 위협 모델에 넣어야 한다.

대응: 원래 Security V2를 수정하지 않고 새 정책은 별도 ID로 관리한다.
실제 Q/P 값, 비밀키·오차분포, evaluation key의 모듈러스를 기록한다.
처음에는 정직하게 계산하는 서버와 클라이언트 비밀키 모델로 한정한다.
새 백엔드와 bootstrapping은 지원 범위를 입증한 뒤에만 주장한다.

### R9. 재현성은 실제 clean clone에서도 성립하는가?

원본에는 미추적 원고·스크립트·증거가 많았다. Git HEAD만 동결하면 이를 놓친다.
복사한 Go 소스의 첫 테스트는 무시된 results/와 외부 compiler fixture가 없어 실패했다.
필요 fixture를 원본에서 읽어 복사한 뒤 해당 패키지들이 통과했다. 이는 코드 결함으로
오인하면 안 되지만, 소스만 받은 독자에게 재현 장벽이 있는 것은 사실이다.
README는 오래된 simulation 단계와 pending 상태를 담고 있어 최종 논문보다 오래됐다.
원본 .venv의 NumPy/scikit-learn도 최종 실험의 고정 버전과 달랐다.

작업공간에 이미 독립 runner 재생, 분석적 bound 전파, exact security estimator를
시도한 증거가 있다. 다만 `independent_machine_replay_v1`은 새 CKKS 실험 없이
raw dataset/무시 ledger 재생을 수행하지 않았다고 명시하고, 분석적 readiness는
primitive derivation 0/50·proof-eligible 0/50으로 기록한다. exact estimator도
Lattigo의 Gaussian truncation을 모델링하지 않아 보안 claim을 제한한다.
따라서 이 작업들을 “전혀 하지 않은 일”로 다시 제안해서는 안 된다. 미완료된
주장 범위를 닫는 것이 후속 목표다.

대응: 전체 로컬 보존본, 파일 해시, 역사적 source 복사, 새 독립 환경,
실험별 protocol/source/model/data/출력 결속, 재생성 명령을 남겼다.
원래 문서·환경을 소급 수정하지 않는다.

동결 작업 중 장비 재시작으로 과거 V7/V8 자동 서비스가 운영 상태와 로그를 갱신한
문제도 발견했다. 과거 자동 시작 5개를 해제하고 운영 파일 7개는 변경분 보관 후
초기 내용으로 복구했다. 이는 최종 논문 증거의 수치 불일치와 구분해야 한다.
Git 객체 payload는 같지만 내부 수정 시각과 Codex 추적 ref에는 차이가 남았다.
전체 보존본의 내용 검증과 현재 작업공간의 내부 메타데이터 동일성은 별개의 판정이다.
근거는 `SOURCE_STATE_RESOLUTION.json`, `OPERATIONAL_STATE_RECOVERY.json`이다.

## PDF 편집 점검

본문 과학 값은 확인한 frozen 사실과 부합한다. 개선점은 DeciProtect 문서에만 기록한다.
1쪽 발행 정보와 접수일은 placeholder이며 빨간 페이지 번호가 보인다.
running title은 첫 페이지의 최종 제목과 다르다. 8쪽 “만족했다제안”에 문장부호가
빠졌고, 마지막 12쪽은 Lattigo URL의 `o.`만 넘어와 사실상 빈 페이지다.
4.3절의 “모든 선택용 입력”은 앞서 정의한 V_delta 범위와 혼동될 수 있다.
초기 구성 계산의 핵심 식을 본문 대신 재현 자료로 넘긴 선택도 자족성을 약하게 한다.
실제 제출본의 편집 지침 충족 여부는 학회 편집부의 확인 항목이며 여기서 원본을 고치지 않았다.

## 검토 범위의 한계

전체 저장소의 파일을 열거·해시하고 보존하지만, 외부 라이브러리 및 빌드 캐시의
모든 줄을 사람처럼 정독했다는 뜻은 아니다. 의미 검토는 최종 PDF 전체, 동기화 lock,
주요 구성·검증·backend·다중 클래스 경로, 원시 사례·키 ledger, 시간 측정 record,
고정 protocol과 주요 대조군·음성 결과에 집중했다. 독립 장비의 새 성능 실험과
모든 외부 compiler 재빌드는 이번 검토에서 완료한 것으로 계산하지 않는다.
