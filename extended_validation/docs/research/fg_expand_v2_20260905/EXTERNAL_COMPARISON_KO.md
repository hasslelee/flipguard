# 대표 외부 비교: 공식 EVA와 독립 제안 선택

기존 공통 다항식과500/500입력을 재사용하여 EVA 공식 compiler/native SEAL을 새로 실행했고, 제안 기법도 기존 원래 정책으로 구성을 독립 선택했다. **두 방법 모두 별도 적용 영역498입력·1,494키 관측에서 판정 변화와 입력별 오차 위반이0회였다.** EVA가 실패해야 한다는 결론을 전제하지 않았다.

프로토콜은 `FG_EXPAND_V2_EVA_NATIVE_20260905`다. 공식 EVA commit `4cd3254c9c51340ae30c451495ce5378135758c0`의 기존 빌드를 DeciProtect의 ignored work에 복사했다. Docker는 `/home/ckks2/deciprotect`만 mount했고 원본에서 실행하지 않았다. 연결 검사는 첫 시도에 통과했다. 원본 및 완료 외부 기록은 그대로 보존했다.

A는 기존 V8에서 사전 지정한 input scale30·output range20 및 security_level128을 유지해 공식 `CKKSCompiler.compile`이 산출한 구성이다. 출력은 `z=.8x0−.5x1+1.2x2−.3`, `score=.5+.197z−.004z³`다. B는 같은 가중치·전처리·출력·입력에 대해 원래 DirectPolicyV2가2회 후보를 평가해 독립 선택했다. 두 경로의 평문 출력은 해당 수식으로 독립 재계산했다. Fashion 모델의 재현이라고 하지 않는다.

EVA에는 우리 판정 gate를 선택 조건으로 추가하지 않았다. 사용자 제공 scale/range·native compile/runtime feasibility·128bit 목표가 원래 요구 조건이고, 응용의 별도 수치 허용값을 새로 만들어 붙이지 않았다. 공식 테스트 파일의 MSE<.01은 일반 compiler 수용 규칙과 다르다. 아래 판정·마진 조건은 EVA 결과에 대한 **사후 평가**다.

| 방법·입력 역할 | 전체 / 적용 / 경계 | 적용 판정 변화 | 적용 오차 위반 | 경계 판정 변화 | 최대 절대오차 | RMSE |
|---|---:|---:|---:|---:|---:|---:|
| EVA 선택용 | 500 / 496 / 4 | 0 | 0 | 0 | 0.00117510 | 0.000143419 |
| 제안 최종 후보 선택용 | 500 / 496 / 4 | 0 | 0 | 1 | 0.0184877 | 0.00769958 |
| EVA 별도 | 500 / 498 / 2 | 0 | 0 | 1 | 0.00110412 | 0.000140220 |
| 제안 별도 | 500 / 498 / 2 | 0 | 0 | 2 | 0.0192562 | 0.00732924 |

변화/위반은3키 합산 관측이다. 별도 경계에서 바뀐 고유 입력은 두 방법 모두1개다. 판정 변화와 여유 조건 위반을 합치지 않았다. 이 결과는 EVA의 수치 오차가 더 작은 경우에도 두 방법 모두 적용 영역 판정을 유지할 수 있음을 보여준다. 제안의 수치 오차 우월성·경계 보존·외부 방법에 대한 일률적 우월성은 지지하지 않는다. 기존 PDF의 S20 133회는 다른 특정 설정의 과거 선택용 결과이며 이번 A에 재라벨링하지 않았다.

EVA 산출 N=8192, prime bits `[50,30,30,30,50]`, 공식 native schedule·1024벡터 중500입력 포장이다. B는 원래 Lattigo 스칼라 복제 경로다. 같은128bit 목표지만 실제 키/오류 분포·assessment가 동일하다고 확정하지 않았으며 N/Q/P만 같아도 schedule·scale 관리는 같지 않다. **출력 의미가 같은 실제 외부 실행 비교**로 분류하고 완전히 통제된 보안/실행 경로의 성능 비교는 보류한다.

구성 준비는 EVA compile 약0.00608초, 제안 선택 약169.33초였다. B 선택 시간 일부에는 기록된 Fashion 시작 오류의 중첩이 있어 진단치로만 유지한다. 별도 B 실행 wall은84.78초이며 EVA의 암호화·평가·복호화·키 생성 원시 시간은 CSV와 `EXTERNAL_RESULTS.json`에 있다. 서로 다른 packing/backend의 수치를 선택 기준만의 비용 효과로 비교하지 않는다. 불리한 시간이나 경계 결과를 삭제하지 않았다.

선택용/별도500입력은 이미 과거 V8에서 노출된 공통 합성 자료다. 새 독립 자연 데이터의 일반화나 Fashion 분류 정답률 개선 증거로 쓰지 않는다. 원시 입력·모델·소스·컴파일 산출·파라미터·키 문맥·각 입력의 점수와 실제 명령이 이번 run에 연결된다. 검증 명령은 `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/analyze_external_fg_expand_v2.py --check`다.
