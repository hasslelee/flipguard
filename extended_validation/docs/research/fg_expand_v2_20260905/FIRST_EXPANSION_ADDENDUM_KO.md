# 첫 확대의 제한적 원시 재분석

기존 `scripts/analyze_fg_expand_v1.py --check`를 읽기 전용으로 실행하고 기존 점수·모델로 재집계했다. 새 CKKS 실행은 0회다. 완료 보고서·원시 결과·모델은 변경하지 않았다. 이번 추가 자료는 `FIRST_EXPANSION_REANALYSIS.json`, `FIRST_MARGIN_DISTRIBUTIONS.csv`, `FIRST_NUMERICAL_CANDIDATES.csv`, `FIRST_SCALE_PAIR_VIOLATIONS.csv`다.

| 별도 평가 합계 | 고유 사례–입력 쌍 | 입력–키 관측 |
|---|---:|---:|
| 적용 영역 | 820 | 2,460 |
| 초기 판정 변화 | 70 | 201 |
| 초기 입력별 오차 위반 | 228 | 675 |
| 선택 후 적용 영역 판정 변화·오차 위반 | 각각0 | 각각0 |
| 선택 후 경계 판정 변화 | 1 | 1 |

전체 별도 입력은1,024 사례–입력 쌍, 키 합산3,072관측이다. 경계204쌍을 적용 영역 성공에 더하지 않았다. 역할 alias 네 개를 독립 암호화 실행 네 개로 세지 않았다. 실제 고유 감사 후보는 선형 사례마다2개, MLP 사례마다1개다. 초기201→선택0은 **우리 초기/선택 구성의 내부 효과**이며 EVA·HEIR 등의 실패 수가 아니다.

선택32개 중 적용 입력은 Spambase 선형31, HTRU2 선형32, Spambase MLP11, HTRU2 MLP32개였다. Spambase MLP의 작은 적용 범위는 별도 평가에서만 생긴 현상이 아니다.

| Spambase MLP 역할 | 전체 / 적용 | 마진 중앙값 | 마진 최대 |
|---|---:|---:|---:|
| 학습 | 3,660 / 1,089 | 0.000538974 | 0.197 |
| 개발 | 256 / 70 | 0.000470097 | 0.120307 |
| 선택 | 32 / 11 | 0.000613909 | 0.00731407 |
| 별도 | 256 / 75 | 0.000572160 | 0.0359921 |

`scripts/build_fg_expand_v1.py`는 학습 원특징으로 표준화를 학습하고, 표준화된 학습 자료의 liblinear 계수 절댓값 상위16개를 선택했다. 두 Spambase 모델의 0-based 특징은 `[3,6,15,22,24,25,26,28,40,41,43,44,45,52,53,55]`다. 16은 사전에 정한 기존 지원 모델·실행비용 범위의 실험 선택이며 최적 특징 수나 보편적인 backend 한계라는 뜻은 아니다.

MLP의 출력 scale은 학습 전체의 최대 절대 logit의 역수 `0.0006540689212219475`다. 출력 함수 `0.5 + 0.197 * scaled_logit`에 이 전역 scale이 적용되어 대부분의 점수가 .5 가까이 모인다. 개발 정답률 약91.8%와 유한 출력은 작은 마진과 함께 존재한다. 원래1200epoch 완료·경고 기록과 이 범위를 분리해야 하며, 작은 마진 자체를 미수렴이나 구현 실패라고 판정할 근거는 없다. 학습 손실 전 과정이 원시에 없으므로 수렴을 새로 증명했다고 하지 않는다. delta/rho/scale/모델/입력을 바꾸지 않았다.

Spambase 선형의 scale24·N13·Q7 수용 후보 최대오차는 `0.005227238903242393`, scale28·N14·Q7 거절 후보는 `0.0010662065870605808`이었다. 같은 선택32입력·같은 원래 polynomial score 기준이며 두 후보 모두 전체 최대오차와 적용31입력의 최대오차가 같았다. 후자의 적용9입력에서25키 관측이 입력별 여유 조건을 위반했고 판정 변화는0회였다. 원시25행에 sample ID·키 번호·후보·마진·오차·예산을 연결했다.

**실제 최소 최대오차 후보는 네 사례 모두 SAFE**였다. 두 선형은S32·Q8·N14, Spambase MLP는S32·Q7·N14, HTRU2 MLP는S32·Q6·N14였다. 따라서 위 한 쌍으로 “최소 오차 방법은 실패한다”거나 “scale을 높이면 정확성이 나빠진다”고 일반화할 수 없다. N·Q·새 키도 함께 바뀌었으며 한 지표의 정렬과 입력별 수용 정렬이 다를 수 있다는 유한 관측이다.

V2에서 고정한 개발 FP16 정밀도 기준을 기존 후보에 사후 적용한 결과도 추가했다. 두 선형에서는 수치 기준이S32·Q8 후보를 선택했으며 제안 조건도 통과했다. Spambase MLP에서는 기존 초기와 같은 후보, HTRU2 MLP에서는S24·Q6 후보를 골랐다. 이는 기존32후보 전체를 이미 평가한 자료의 재분석이다. 새 제한예산 온라인 선택이나 독립 검증으로 표시하지 않는다. 이미 감사한 동일 후보의 결과만 재사용하며 나머지 수치 선택 후보의 별도 감사는 **미평가**로 남겼다. 누락된 결과를0회 실패로 채우지 않았다.
