# 이번 확대에서 답한 질문과 남은 한계

최종 수치는 `REPORT_KO.md`와 원시 재계산 표를 따른다. 아래는 미리 정한 승리
문장이 아니라, 이번 비교가 허용하는 해석의 범위다.

| 심사 질문 | 확인 근거와 답변 범위 |
|---|---|
| 기존 연구는 판정을 전혀 고려하지 않았는가? | 그렇게 주장하지 않는다. 관련 연구 기준표는 정확도/판정 결과 보고, 구성 수용 조건, 입력별 마진 조건을 구분한다. FHE-Agent는 정확도 차이와 수치 조건을 선택에 사용하며 활성화 고정에 관한 이전 설명도 정정했다. 원문 미언급과 구현 부재는 다르다. |
| 201→0은 어떤 외부 방법을 이긴 것인가? | 첫 확대의 우리 초기 구성과 최종 선택 구성 간 변화다. 초기 합성에도 마진 정보가 남아 있다. 외부 연구의 오류로 바꾸지 않는다. |
| 왜 FP16 오차를 기준으로 삼았는가? | 개발 출력의 명시적인 계산 정밀도 기준이며 단위가 다른 논문 허용값을 복사하지 않았다. CKKS/test 결과 이전에 고정했다. 응용 허용 오차의 정당성이나 특정 선행 방법의 완전한 재현은 입증하지 못한다. |
| 수치 기준 대조군에도 우리 마진 정보가 들어갔는가? | 공통 후보 생성에는 들어간다. 비교가 분리하는 것은 그 범위 안의 수용 조건이다. 완전히 판정 정보를 쓰지 않는 생성·선택 전체와의 비교로 해석할 수 없다. |
| 유한 후보를 모두 보고 고른 방법을 온라인 선택과 비교했는가? | 평가 범위와 실제 후보 수·비용을 따로 공개했다. 제안은 원래 최대 4회 최초 SAFE 규칙이고 유한 비교군은 전체 평가 후 argmin이다. 선택 때 관측한 최소 시간과 별도 paired 시간을 분리했다. |
| 같은 구성들이 선택되면 무엇을 입증하는가? | 새 데이터/모델에서의 실행 가능성과 별도 입력의 관측 범위를 보강한다. 그 사례에서는 수용 조건 차이에 따른 구성 개선을 관측하지 못한 것으로 보고한다. 성공 입력 수 증가만으로 조건의 우월성을 주장하지 않는다. |
| 더 작은 최대오차는 항상 더 안전한가? | 첫 확대의 scale24/28 한 쌍에서는 전역 최대오차의 순서가 입력별 조건 수용과 일치하지 않았다. 하지만 실제 최소 최대오차 후보는 네 사례 모두 수용됐다. scale 증가 일반의 악화나 최소오차 방법 일반의 실패는 뒷받침되지 않는다. |
| 평문 모델이 틀렸는데 판정만 유지하면 무슨 의미인가? | 평문 분류 정답률/클래스별 품질을 별도로 공개한다. 판정 일치는 CKKS로 바뀐 계산의 충실도이며 학습 모델 자체의 정확도 보증이 아니다. |
| 학습이 잘됐는가? | 기존 8epoch의 모든 손실과 개발 성능, 유한 출력, 세 초기값을 공개했다. 고정 epoch 완료를 수렴으로 바꾸지 않는다. 시험 성능을 보고 모델이나 seed를 교체하지 않았다. |
| 10,000개를 넣으려고 N을 키웠는가? | 아니다. 기존 500입력 packing을 20배치로 나눴다. N은 선택 자료의 원래 합성·보안 정책으로 정했다. 784입력/10출력 암호문 수, 유효 slot과 padding을 구분한다. |
| 키 반복과 slot을 독립 표본으로 셌는가? | 아니다. 후보·배치마다 새 키 3개이므로 완주한 후보는 60문맥, 입력당 3관측이다. 세 초기값은 한 데이터·구조 그룹이며 독립 데이터셋 세 개가 아니다. 새 위험 상한이나 통계적 동등성을 주장하지 않는다. |
| 적용 영역을 방법마다 유리하게 바꿨는가? | 같은 평문 모델·gap>0.001로 미리 정의하며 모든 방법에 공통이다. 경계 입력도 전체 분모와 별도 사건 표에 남긴다. 정책·출력 스케일·입력을 사후 조정하지 않았다. |
| 판정은 같은데 조건만 위반한 입력이 있는가? | 입력별 판정 변화와 보수적인 오차 조건 위반을 별도 계산하고 실제 logits를 연결한다. 해당 유형이 없으면 미관측으로 기록하며 만들기 위한 조정을 하지 않는다. |
| 실제 외부 프로그램과 비교했는가? | 이번 EVA는 공식 compiler와 native SEAL의 실제 암호화 실행이다. 제안은 같은 공통 다항식에서 독립 선택했다. 기존 HEIR 파라미터 이식과 혼동하지 않는다. Fashion 그래프 전체의 EVA 재현은 수행하지 않았다. |
| 외부 방법의 조건을 꺼서 약하게 만들었는가? | EVA의 기존 scale30/range20 및 native security 설정을 유지했다. 우리의 판정 조건은 사후 지표이고 외부 선택 조건으로 추가하지 않았다. 과거 S20 실패를 이번 비교에 대입하지 않았다. |
| EVA와의 시간 차이가 선택 기준 효과인가? | 그렇게 해석하지 않는다. 두 경로의 packing·schedule·보안 assessment가 동일하지 않다. 외부 B 선택의 일부 중첩 시간도 숨기지 않고 진단으로만 남겼다. Fashion 공통 경로 paired 비교와 분리한다. |
| 보고된 시간은 서비스 지연시간인가? | 아니다. 원래 harness의 로컬 배치 구간이다. 키 준비와 동형 연산을 나누고 total에 들어간 평문 참조/GC 잔여를 설명했다. 미측정 네트워크·큐를 0으로 놓지 않는다. |
| 오류가 나자 불리한 결과를 버렸는가? | 중첩으로 중단한 첫 시도와 reader 오류, source 설명 필드 오타를 보존했다. 완료 후보 계산은 재실행하지 않았다. 실제 과학적 거절과 프로그램 오류를 구분한다. |
| 무엇이 아직 확인되지 않았는가? | 다른 수치 예산에 대한 민감도, 완전히 별도의 생성기를 가진 공정한 전체 방법 비교, Fashion 전체 그래프의 외부 native 연결, 다른 장치·입력 분포에 대한 일반화는 미확인이다. 이 작업 종료 후 자동으로 새 대규모 실험을 시작하지 않는다. |

이 표는 결과를 해석하는 경계이며 새로운 수용선이나 추가 합격 조건이 아니다.
관측된 개선·동일·악화를 원래 원시 자료와 함께 평가해야 한다.
