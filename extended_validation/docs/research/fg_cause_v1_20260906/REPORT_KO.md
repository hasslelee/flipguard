# A/B/C 무차이·Bank 실패·구성 비용의 원인 분석

**핵심 판정 개선은 이번 분석에서도 새로 확인되지 않았다.** 완료한 A/B/C 결과를 그대로 유지한다. 표형 A/B 무차이에는 조건 포함 관계와 첫 후보 종료가 함께 작용했고, Fashion에서는 포함 관계 없이 실제 오차가 작아 둘 다 통과했다. Bank C의 합성 입력 실패는 실제 출력 오차가 판정 여유를 초과한 사건이다. 충분조건 자체의 반례가 아니다.

**우선 검토할 최소 보완은 ‘동일 비용 등급 안에서 정밀도 여유를 사용하는 기존 비활성 정책’ 하나다.** 같은 N·Q/P 개수·실행 경로에서 낮은 scale이 비용 이득을 주지 않은 Bank와, 같은 비용 등급에서 더 큰 오차 여유를 보인 기존 선택 후보들이 근거다. 이는 이미 소스에 있는 선택적 정책이며 새 알고리즘이나 국제적 기여가 아니다. C보다 안전한 결과를 얻을 가능성과 B보다 추가 가치가 있다는 주장은 다르다. 후자는 현재 미확인이다. **정책 활성화·C 변경·새 CKKS는 하지 않았다.** 사분위 선택 실험도 실행하지 않았다.

## 2. A/B가 같았던 이유

### 같은 출력·입력·키 기준에서의 포함 관계

한 후보의 같은 실제 출력 자료에 대해 A는 각 키 r마다 **선택 입력 전체, 출력 전체**의 최대 절대오차가 `τ` 이하인지 검사하고 세 키 모두 통과해야 수용한다. B는 같은 평문으로 정의한 비어 있지 않은 `Vδ`에서 세 키 모두 판정 일치 및 입력별 조건을 요구한다. A/B의 실제 선택 실행은 별도 키이므로, 아래 포함 관계는 **동일한 관측 출력에 두 조건을 적용할 때**의 명제다. 서로 다른 키 실행의 오차가 동일하다는 가정은 하지 않는다.

이진 score는 `D=I[score≥0.5]`, `γ=|score−0.5|`, `Vδ={γ>0.001}`, `ρ=0.5`이다. 같은 유한 출력에서

`E_r(x) ≤ max E_r ≤ τ < 0.0005 = ρδ < ργ(x) < γ(x)`

이므로 A 통과는 적용 영역에서 B의 **엄격한** 오차 부등식과 판정 일치를 함께 함의한다. A의 `≤`와 B의 `<`를 바꾸지 않았다. 전체 선택 입력을 쓰는 A의 범위는 B의 적용 영역을 포함한다. 실행 가능성·보안 수용·정상 유한 출력·비어 있지 않은 적용 영역은 이번 공통 조건이다. 역방향 포함은 성립하지 않는다.

| 모델 | 개발 τ 최대오차 | 선택 적용/전체 | 최소 적용 마진 | A⇒B 포함 |
|---|---:|---:|---:|---|
| Spambase 선형 | 0.000242250882 | 31/32 | 0.001206859919 | 성립 |
| HTRU2 선형 | 0.000228231834 | 32/32 | 0.016869011075 | 성립 |
| Spambase MLP | 0.000242210412 | 11/32 | 0.001074939331 | 성립 |
| HTRU2 MLP | 0.000238269616 | 32/32 | 0.004325076103 | 성립 |

Fashion은 10개 logit의 최고 클래스 i와 **모든 경쟁 클래스 j**에 `e_i+e_j<ρ(z_i−z_j)`를 적용한다. 이때 최대오차 `τ`로부터 얻는 상계는 `2τ`다. 세 모델의 주 τ는 약 0.0262–0.0296으로 `2τ≤ρδ`도, 실제 선택 최소 마진에 대한 `2τ<ρ min γ`도 만족하지 않는다. 이진 논리를 복사할 수 없다. 실제 B30의 최악 예산 사용률은 두 선택 블록에서 seed0 0.00706/0.02118, seed1 0.00372/0.00634, seed2 0.00772/0.00481로 1보다 작았다. 즉 포함 관계가 없지만 측정된 오차가 충분히 작았다.

RMSE는 개별 오차 상계가 아니다. 같은 키의 스칼라 출력 수 M에 한해 `max E≤sqrt(M)·RMSE`라는 별도 상계를 적용할 수 있다. 선택 자료에서는 이 상계와 실제 최소 마진을 함께 쓸 때 표형 3개에 조건부 포함이 성립하지만 Spambase MLP와 Fashion에는 성립하지 않는다. 입력 수가 달라지는 감사에도 그대로 옮길 수 없고, 세 키 RMSE를 합친 평균으로 ‘각 키 통과’를 대신할 수 없다. 이 결과는 `AB_RELATIONS.csv`에 분리했다.

### 수용 집합 차이와 실제 종료 위치

- A30/B30은 14/14 사례–블록, A40/B40도 14/14에서 같은 구성이다. 모든 A/B 실행이 첫 후보에서 수용되어 이후 순서를 탐색하지 않았다.

현재 비교는 강한 수치 기준과 보수적인 시작점 아래 A/B의 실제 선택·판정 차이가 없음을 확인했다. 네 표형에서는 A를 통과한 후보를 판정 기준 B가 추가로 탈락시키는 질문 자체가 이 조건 관계로 막힌다. 수치 기준을 느슨하게 조정하여 A의 실패를 만들지 않는다. 근거: `cmd/contribution-case/main.go::scalarNumeric/multiNumeric`와 선택 루프(약 57–82, 260–294행), `internal/certify/multiclass_decision_contract.go::AggregateObservedMulticlassCandidate`의 `minimumCap < marginUtilizationCap`, `AB_RELATIONS.csv`, `CANDIDATE_RECONSTRUCTION.csv`.

확인한 원인은 (a) 선택16의 검증 마진 범위가 뒤 입력을 대표하지 못했고, (b) 낮은 정밀도에서 관측된 반대 방향 출력 오차가 작은 순위 차이를 넘었다는 것이다. 아직 분리하지 못한 것은 입력 인코딩/암호화 오차, 은닉 affine의 스칼라 곱·누적 오차, 제곱·재선형화·리스케일 오차, 최종 logit 누적의 각각의 기여다. 기존 JSON은 최종 출력과 파라미터를 저장하지만 중간 복호값·단계별 오차 추적을 저장하지 않았다. 이를 분리하려면 향후 승인된 한 실행에서 같은 입력·키 문맥의 각 경계 중간값과 scale/level을 계측해야 한다. 지금 자료로 소급 복원하거나 새 실행을 자동 시작하지 않는다.

합성 좌표·반경·정수 격자·범주 보존은 기존 검증 결과대로 유지한다. 공동 고객 타당성과 합성 정답은 미확정이다. 6197의 부모는 평문 클래스1, 합성은 평문 클래스0이다. 부모 레이블을 합성 정답으로 사용하지 않고 HEDiff Eq.2의 ‘정답인 평문’ 사건도 합성에 부여하지 않는다. 충분조건을 만족하면서 뒤집힌 반례는 여기서 관측되지 않았다.

## 4. 다음 선택 입력 정책의 평문 검토

기존 16개는 NearMiss 후 shuffle(random_state=42), 마지막 20% test 안의 **위치0–15**였다. 마진별 추출이 아니었다. 뒤 감사16–47, 개발48–175와 분리되어 있었다. 전체 원본의 complete-case 처리·LabelEncoder·float32 min-max와 NearMiss의 레이블 사용은 분할 전에 이루어졌다. 그 이력을 유지한 분석이므로 데이터 누수가 없는 새로운 일반화 검증으로 표현하지 않는다.

| 선택 입력의 검증 범위 | Bank 선택 최소1.0558, 개발·후속에 훨씬 작은 마진 | 설명 보완 필요. 사분위4×4의 추가 효과는 이번 평문 규칙에서 미관측 |
| 초기 정밀도 추정 | Bank는 해당 선택에서만 충분, Fashion0는 작은 기존 후보도 수용 | 경험적 한계. 추정 항별 과대/과소 원인은 미분리 |
| 비용 등급을 충분히 반영하지 않는 선택 | Bank 동일 등급에서 낮은 정밀도 이득 없음; Fashion0는 N 경계 상승 | 최소 정책 검토 근거 있음 |
| 구현·평가 문제 | 조건/선택 결과 재계산은 일치. 개발 CKKS·중간 암호화 오차 없음, 전체자료 전처리 이력 있음 | 검사 통과를 위험/성능 보장으로 바꾸지 않음 |
| B 대비 추가 가치 | Bank B는 같은 비용으로 이미 성공, Fashion B는 더 저렴 | 현재 확인 불가. C의 실패 제거와 분리 |

### 우선안 하나: 같은 비용 등급 안에서 정밀도 여유 사용

검토 대상은 **이미 소스에 구현되어 있으나 C에서는 `precision_slack_mode="none"`인** `maximizePrecisionWithinMinLogNTier`다. `synthesis.go` 530–532행에 선택적 분기, 566–627행에 해당 함수가 있다. 이번에는 이 함수를 호출하거나 활성화하지 않았다. 기존 C의 사실로 기록하지 않고 별도 변형 가설로 제시한다.

변형을 검토한다면 입력·마진/민감도 분석과 최초 최소 구성을 그대로 만든 뒤, 그 N·Q/P 개수·실행 경로·요구 레벨을 유지하는 범위에서 기존 보안/백엔드 정적 검사를 통과하는 가장 큰 scale을 첫 실제 평가 대상으로 삼는 변경 하나만 한다. 평가의 판정/오차 조건, rho/delta, 3키, 실패시 기존 조정, 최대4회와 첫 수용 종료는 유지한다. 입력 층화, 허용값 변경, 보안 완화, 더 작은 N 탐색은 함께 넣지 않는다.

Bank는 단순 비트 산술상 S33일 때 QP210으로 N13 한도214 이내이고 S34는216으로 넘는다. 이는 정적 비트 예시이며 S33의 실제 소수 생성·암호화 수용 결과는 **없다**. 실행 시간도 자동으로 같다고 보장하지 않는다. C S20을 사후 S33으로 교체하거나 S33을 기존 선택 구성으로 표시하지 않는다.

관측 원인과의 연결은 ‘비용을 줄이지 못하는 낮은 정밀도에 머무를 필요가 있는가’다. 선택 입력 누락을 해결하거나 Bank 스트레스 실패가 반드시 사라진다고 주장하지 않는다. Fashion0의 높은 N 문제도 이 변경으로 해결되지 않는다. 그 문제를 해결하는 하향 비용 탐색은 별도 변경이므로 이번 우선안에 섞지 않는다.

**왜 단순 B나 통상적 정밀도 증가로 충분하지 않은가? 현재 충분하지 않다고 말할 근거가 없다.** Bank B30은 같은 비용 등급에서 이미 판정·오차 조건을 통과했고 이 변형이 B보다 낫다는 증거는 없다. 통상적인 정밀도 증가의 구현 사례이고 기존 선택적 코드와 중복된다. 가능한 검증 대상은 C 대비 오차 여유/실패 감소, 그리고 B와 같은 판정 목적에서 낮은 N의 이점을 유지할 수 있는지다. Bank 하나에서 C의 실패만 없애면 ‘기존 C의 강건성 보강’으로만 분류한다. 새로운 국제적 기여나 A/B 판정 조건의 독자적 효과로 인정하지 않는다.

## 7. 사용자 확인 뒤에만 가능한 검증 계획

**실행하지 않은 계획**이다. 하나의 변경만 검증하기 위해 고정 Bank 모델에서 C, 같은 등급 정밀도 여유 변형 C′, 단순 B30을 비교하는 한 묶음을 우선 후보로 둔다. 원래 선택16을 세 군에 동일 적용하고 입력 층화를 동시에 도입하지 않는다. 선택에 알려진 실패 입력을 넣지 않는다. 원래 C는 수정하지 않고 별도 variant ID로만 구현한다.

- 같은 선택 상한4·3키와 원래 보안/수용 조건을 유지한다. C′에서 실제로 같은 N·Q/P 개수·packing·레벨 일정이 유지됐는지 검증하고 정적 분석·키 준비 비용도 별도 계측한다.
- 구성 고정 뒤 이번에 분리해 두고 출력조차 보지 않은 예약684개를 모든 군의 공통 감사로 사용한다. 이 풀도 원래 전체자료 전처리 이력의 영향은 받았으므로 누수 없는 일반화 모집단이라고 부르지 않는다. 희소 작은 마진이나 실패가 없으면 판정 이점은 미관측으로 남긴다.
- 기존 스트레스16은 이미 노출된 **회귀 점검**으로 별도 보고한다. 이를 독립 감사나 일반 고객 발생률로 세지 않는다. 여기서의 실패 제거만으로 B 대비 추가 가치를 인정하지 않는다.
- 판정 변화, 충분조건 위반, 예산 사용률, 적용 영역, 고유 입력과 키 관측, 실제 후보 수, 전체 선택 비용, 준비와 분리한 대응 추론 비용을 비교한다. 기존 예열1·측정6·키3 대응 규격을 기본으로 삼고 실행 상한은 실제 variant 정적 후보 수를 확인한 뒤 본 평가 전에 고정한다. 이 문서는 아직 암호화 protocol이나 실행 승인이 아니다.
- C′가 같은 비용 등급을 벗어나거나, 판정/조건 위반이 늘거나, 추가 분석·선택·추론 비용에 비해 확인한 이점이 없으면 우선안을 채택하지 않는다. B와 결과가 같고 선택·추론 비용도 줄지 않으면 **추가 가치 미확인**으로 끝낸다. C 대비 같은 판정을 유지하며 조건 여유만 커지면 수치 여유 보강으로만 기록한다.

이번 증거는 새 정책의 성공률·미래 위험 상한·시간 동등성·국제 경쟁력을 확인하지 않는다. 더 큰 모델/데이터나 새 compiler·bootstrapping·운영 queue로 자동 확장하지 않는다.

## 8. 결론·산출물·검증

1. **방법 변경 없이 평가 설명을 보완할 부분:** 이진 A⇒B 포함, 첫 후보 종료, Fashion의 실제 작은 오차, 적용 영역 한정, Bank 조건 위반과 충분조건 오류의 구별, 규모가 아닌 실제 N/Q/P/경로에 따른 비용 설명이다. A/B 핵심 판정 개선 미관측을 유지한다.
2. **기존 구성 선택 연구 안에서 최소 변경 검토 근거가 있는 부분:** 같은 구조적 비용 등급에서 정밀도 여유를 사용하는 기존 비활성 정책. 관측 후보의 여유 차이와 Bank의 비용 무이득이 근거지만 정책 효과는 미실행이다.
3. **현재 추가 가치를 확인할 수 없는 부분:** Bank에서 B보다 나은 판정·선택·추론, 사분위4×4의 균등16 대비 작은 마진 포함 효과, 중간 CKKS 오차의 단계별 원인이다. Fashion0의 N 상승 문제는 별도 미해결로 남긴다.

집계표는 `AB_RELATIONS.csv`, `CANDIDATE_RECONSTRUCTION.csv`, `SYNTHESIS_PATHS.csv`, `BANK_CLASS_ERRORS.csv`, `BANK_INPUT_PLAINTEXT.csv`, `BANK_FEATURE_RANGES.csv`, `BANK_STAGE_SUMMARY.csv`, `BANK_CANDIDATE_POOL.csv`, `BANK_PLAINTEXT_SELECTIONS.csv`, `BANK_POLICY_COVERAGE.csv`, `BANK_POLICY_ANALYSIS_ONLY.csv`, `BANK_SELECTION_ALTERNATIVES.csv`, `COST_CAUSES.csv`, `OBSERVED_ALTERNATIVES.csv`다. 모든 키 관측을 독립 입력처럼 합산하지 않았다. `ANALYSIS.json`·`SUPPLEMENT.json`은 기계 판독 결과다.

재현 명령은 `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/analyze_fg_cause_v1.py --write`, 이어서 `OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/supplement_fg_cause_v1.py`다. 둘 다 새 폴더 전용 배타 쓰기여서 완료 파일 위에 재실행할 수 없다. 읽기 검증은 `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/verify_fg_cause_v1.py`다. 모델·입력·protocol·소스·원시 파일은 run의 `READ_BINDINGS.json`, `SUPPLEMENT_READ_BINDINGS.json`, `SOURCE_REVIEW.json`, `FINAL_VERIFICATION.json`에 연결한다.

첫 평문 분석 시 내부 결과3표 작성 뒤 함수 인자명 오류로 중단되었다. 미사용 후보 출력 계산 전이었으며 `analysis_attempt_01`에 부분 표와 오류를 보존했다. 인자명을 고친 두 번째 분석이 완료됐다. 기존 실험 실패나 새 CKKS 실행으로 세지 않는다.

변경은 새 분석 protocol/run/report, 평문 분석·검증·handoff 생성 스크립트, 현재 sync와 dispatcher에 한정한다. 이전 sync는 `history/`에 보존하고 완료한 A/B/C 보고서는 덮어쓰지 않았다. 최종 검증의 보존 판정과 변경 경로를 따른다. **C 변경 구현과 새 암호화 실험은 사용자 확인 전까지 시작하지 않는다.**
