# 실행 범위와 구현 대응

이번 묶음은 사용자가 명시적으로 승인한 `CKKS_기여검증_Codex_지시문_v1.md`의 실행이다. 최종 기준은 `baseline/journal_final_20260905.pdf`이며 SHA-256은 `0210899a12ff1025db358e1812159ca4af2b5c6095a79e2b7b19200d7e9f3b85`이다. 시작 HEAD는 `b4950499987e06a08075b4a8413ef216e9ab3471`이다. 기존 DP 재계산·유보·큐 연구로 전환하지 않는다. 이번 유한 묶음 종료 뒤 새로운 데이터·모델·방법의 실험을 자동 시작하지 않는다.

## 선택 경로

| 역할 | 후보 생성·진행 | 수용 조건 | 비교의 의미 |
|---|---|---|---|
| A30 / A40 | 독립 생성기, 시작 scale 30 / 40, 매 제안 +4 | 개발 FP16 roundtrip 최대 절대오차 이하, 모든 평가 출력·3개 키 | 독립 대표 수치 기준이며 특정 선행논문의 완전 재현이 아님 |
| B30 / B40 | A와 동일한 생성기·시작·순서 | 최종 PDF의 판정 일치와 입력별 오차 조건, 공통 적용 영역·3개 키 | A–B는 수용 조건을 교체한 효과 |
| C | 기존 초기 합성·제한적 조정, 첫 수용, 최대 4회 | B와 동일 | B–C는 같은 판정 목적에서 선택 절차의 추가 가치 |

모든 역할의 실제 암호화 후보 상한은 4, 후보별 키 반복은 3이다. 기존 7개 모델 모두 두 독립 선택 블록을 실행한다. 정적 생성 실패도 기록하며, 암호화 실패를 좋은 키로 다시 실행해 지우지 않는다. 후보별 모든 키를 완료하되 실행 실패는 별도 상태로 보존한다. 두 선택 블록은 탐색적 반복이며 통계적 우월성이나 위험 상한의 근거로 사용하지 않는다.

`research/contribution_validation/cmd/contribution-case/main.go`의 `select`가 실제 순차 선택을 실행한다. A/B는 `BuildIndependentFacts` → `GenerateIndependentCandidate`, C는 기존 계약 분석 → `Synthesize` → 기존 실행·수용 검사 → 필요할 때 `RepairCandidate`로 진행한다. A/B 생성 입력 자료형은 모델/입력 식별자, 그래프에 필요한 Q 길이·소비 레벨·slot 수, 출력 절댓값 범위뿐이다. 판정 마진·민감도·C 초기 구성·오차 예산을 전달하는 필드는 없다. B가 평가 시 마진을 읽는 것은 의도한 설계이다.

독립 생성기에서 Q 첫 소수 비트는 `max(18, scale + magnitudeBits(max_abs_output) + 3)`, 나머지는 명시한 scale, Q 개수는 실제 백엔드 scale trace의 요구량이다. P는 소수 하나, 비트 수 `max(30, first_Q_bits)`이다. 기존 Q/QP 128비트 보안 envelope와 필요한 slot을 만족하는 최소 logN을 12–15에서 고른다. 60비트 초과 소수를 숨은 scale 변경으로 수리하지 않는다. 생성·보안·백엔드 생성 탈락은 구분한다. 이 규칙은 수치 조건을 만족하도록 최적화한 외부 컴파일러의 재현은 아니다.

시작 30은 기존 일반 `DefaultSynthesisPolicy`의 개발 기본값을 근거로 명시적으로 고정했다. C의 입력별 마진에서 나온 값은 아니다. 보수적 시작 40은 [Microsoft SEAL 공식 CKKS 예제](https://github.com/microsoft/SEAL/blob/main/native/examples/5_ckks_basics.cpp)의 scale 예시에서 가져온 민감도 설정이다. 해당 예제의 전체 파라미터·계산 일정 재현이라고 부르지 않는다. 모든 모델에 같은 두 출발 규칙을 적용한다.

## C와 기존 증거 보존

`PRESERVED_C_CORE_CHECK.json`은 기존 확대용 소스, 새 내부 실행 소스, 새 외부 연결 소스의 핵심 정책·합성·보안·계약·보정·다중 클래스 수용 파일을 바이트 비교한다. 내부 복사본에서 기존 파일 변경은 시간 계측과 원시 키 실행 콜백이다. `SOURCE_LOCK.json`이 실제 내부 실행 소스·바이너리를 결속한다. 동결 결과를 수정하지 않았으며 전체 archive 해시를 반복하지 않았다.

과거 201→0은 내부 초기 구성과 선택 구성의 적용 영역 결과이다. Fashion-MNIST의 과거 조건별 선택 일치, 당시 공통 후보 생성에 남아 있던 마진 정보, 기존 EVA의 적용 영역 무차이와 경계 관측도 보존한다. 이를 외부 방법의 실패로 재명명하지 않는다. 정확한 기존 Spambase S32·Q8·N14와 S24·Q7·N13은 `legacy_fixed/*.json`에서 별도 결속하여 새 감사·대응 시간에 포함한다.

## 입력·정확성·후보 지도

7개 기존 가중치·전처리·분할·판정 정의를 유지한다. 표형 모델은 후보당 선택 32개, 별도 평가 전체 256개이다. Fashion-MNIST는 후보당 선택 500개, 별도 평가 전체 10,000개를 500개씩 20배치로 평가한다. 두 선택 블록을 모두 고정한 뒤 파라미터가 서로 다른 선택 구성만 감사한다. 동일 구성 역할은 alias로 묶는다. 이미 노출된 시험 자료이므로 새 키를 사용해도 새로운 독립 입력 확증은 아니다.

공통 적용 영역은 표형 `|score−0.5|>0.001`, 다중 클래스 평문 top-two gap `>0.001`이다. 표형 오차 조건은 `|CKKS−plain| < 0.5 |score−0.5|`; 다중 클래스는 평문 최고 클래스 i와 모든 경쟁 클래스 j에 대해 `e_i+e_j < 0.5(z_i−z_j)`이다. 실제 판정 불일치와 충분조건 위반을 별도로 센다. 적용 영역 밖 관측과 전체 분모를 함께 남긴다. 비어 있는 적용 영역을 성공으로 처리하지 않는다.

주 수치 허용값은 각 모델 개발 자료에서 기존 정의로 계산한 FP16 roundtrip 최대오차이다. 표형은 score, Fashion은 정규화하지 않은 logit 단위이다. 정확한 수치는 protocol의 `cases[].thresholds`에 있다. RMSE는 별도 기준이다. 표형 네 모델의 주 최대오차 허용값은 모두 `rho*delta=0.0005`보다 작아, 그 수치 조건을 통과하면 적용 영역의 오차 조건도 포함한다. 이 논리적 포함 관계에서 A/B 무차이를 제안 기법의 우월성으로 해석하지 않는다.

실제 선택을 모두 고정한 뒤 독립 scale `[18,22,26,30,34,38,40]`의 49개 후보를 선택 자료로 평가한다. 수치 허용값 민감도는 사전 고정한 `[0.25,1,4]`배이다. 이는 후보 조건 지도이며 제한 예산의 실제 온라인 선택 비용과 구분한다. B가 예산 내 미선택이면 최대 두 단계 추가 진단을 하되 원래 선택 결과를 교체하지 않는다.

## 실행·키·비용

표형 실행은 `ExecuteTabularCandidateWithOptions` → `RunCKKSTabularInference`로, 다중 클래스는 `ExecuteJournalMNISTMulticlassCandidateWithOptions` → `RunCKKSJournalMNISTMulticlassInference`로 연결된다. 원래 평문 참조를 읽는 오프라인 구성 선택이다. 서버 운영 gate나 네트워크 프로토콜을 구현한 것으로 설명하지 않는다.

Lattigo v6.2.0의 파라미터·키 문맥을 매 키 실행마다 새로 만든다. 기본 비밀키 분포는 uniform ternary (`P=2/3`), 오차 분포는 discrete Gaussian (`sigma=3.2`, bound `19.2`)이다. 기존 Security Policy V2는 암호문 Q와 평가키 QP를 모두 검사한다. 실제 Q/P 소수 벡터를 `key_*.json`에 기록한다. 키 번호가 같아도 다른 파라미터·배치의 비밀키가 같다는 뜻이 아니다. 비밀키는 결과에 저장하지 않는다.

Fashion은 feature당 암호문 하나, 총 784개 입력 암호문에 입력을 slot으로 배치하고 10개 출력 암호문을 만든다. 유효 slot과 물리 slot은 원시 summary에 구분된다. 표형은 원래 실행 방식의 입력별 연산을 유지한다. slot이나 동일 키 반복을 독립 환경 수로 세지 않는다.

비용은 계약/합성 분석, 후보 실행, 파라미터 생성, 키 준비, 인코딩·암호화, 동형연산, 복호화·디코딩, 판정/수치 검사, 증거 쓰기와 나머지 wall time을 구분한다. A의 판정 검사는 사후 지표이며 별도 계측한다. B/C의 수치 검사도 사후 지표이다. 실제 실행 wall time에는 이 계측이 포함된다. C의 조정 비용 중 별도 타이머가 없는 부분은 잔여 시간이며 0으로 단정하지 않는다.

선택된 구성은 새 대응 시간 실험으로 평가한다. 입력 20, 예열 1, 측정 6, 독립 키 블록 3, 원래의 균형 실행 순서를 유지한다. 최종 PDF 시간은 인코딩·암호화 + 동형연산 + 복호화·디코딩의 합이고 키 준비는 별도이다. 전체 native total의 추가 처리도 별도로 남긴다. 대응 비율은 각 키 블록 내 동일 입력·회차의 comparator/C 기하평균과 블록별 값으로 제시한다. 모든 이상치를 보존하고 유의성·동등성을 선언하지 않는다. 복사된 V17 metadata의 B3 문구는 과거 필드 값이며, 이번 실제 선택 역할은 `FROZEN_SELECTIONS.json`과 `TIMING_JOBS.json`이 정한다.

네트워크·직렬화 전송·운영 큐 대기는 미측정이다. 0으로 채우거나 실서비스 전체 지연으로 보고하지 않는다. native command wall 상한 12시간, 단일 호출 30분, 메모리 주소공간 8GiB, 새 결과 6GiB, 최소 여유 디스크 8GiB이다. 배치·사례를 순환하며 상한 도달 시 미완료 범위를 그대로 남긴다. 실험 성공 여부 때문에 상한을 연장하지 않는다.

## 외부 한 사례와 스트레스

별도 `EXTERNAL_PROTOCOL_EXACT_LOGITS.json`을 따른다. HEDiff Bank 20→256→2를 공개 절차로 한 번 재학습한다. 공식 가중치가 없어 원래 학습 모델 재현으로 부르지 않는다. 두 logit을 유지하는 항등식 연결은 별도 소스·바이너리이며 내부 동결 실행을 변경하지 않는다. HEDiff는 불일치 탐색 방법이지 구성 선택 경쟁 알고리즘이 아니다. 원래 CKKS 설정의 실행과 공통 Lattigo A/B/C를 구분한다. 원래 설정은 SEAL 기본 보안을 통과하지만 QP 218은 우리 V2 N13 한도 214와 다르므로 동일 보안 정책이나 실행 시간의 인과적 비교를 주장하지 않는다.

각 내부 모델의 첫 별도 입력 16개에서 평문만 사용해 20단계 공통 스트레스를 생성한다. 영상 반경 8/255, 표형 반경은 학습 범위의 0.02배이며 이산 특성은 보존한다. 일반 발생률과 합치지 않는다. 합성 입력의 정답은 미확정이다. 반경·좌표 제약이 실제 이미지 의미나 이메일/물리적 특성의 공동 타당성까지 보장하지 않는다. 모든 결과를 남기며 실패를 선택 자료에 넣어 재조정하지 않는다.
