# 졸업논문 확장 연구 계획

핵심은 그대로 유지한다. **CKKS 암호화 추론에서 실제 응용의 결정이 중요하므로,
명시된 평문 모델의 결정을 보존한다.** 모델·데이터·정밀도 선택은 이 목적에 종속된다.
기존 학회논문은 연구의 1단계로 인용하고, 이번 변경을 소급 반영하지 않는다.
후속 과제 상태는 [GitHub issue 1](https://github.com/hasslelee/deciprotect/issues/1)에서 추적한다.

## 이번 시작 단계에서 실행한 것

1. 최종 PDF 보존, 전체 저장소 동결 작업, 독립 GitHub 저장소 생성.
2. 저널 심사 보고서와 점수, 원시 136개 사례-단계 및 23,454개 시간 짝의 독립 재계산.
3. 두 신규 데이터셋, 선형 분류기와 직접 학습한 square MLP, 세 학습 seed.
4. 평문 oracle를 사용하지 않는 client interval gate와 실제 고정밀도 재계산.
5. 표본 부족, 낮은 비트의 prime 생성 실패, 경계 및 이동 입력, SIMD 비용 실패 기록.
6. 한 입력·한 새 키를 독립 단위로 하는 고정 600회 유한 모집단 위험 감사.

## 데이터와 모델의 우선순위

보안 서비스의 외적 타당성은 UNSW-NB15 또는 CIC-IDS2017의 정해진 시간/호스트
분할로 검증한다. IP, 세션 식별자, 공격 일정 같은 누수 특징을 감사한다.
무작위 행 분할을 실배포 시간 일반화로 표현하지 않는다. 먼저 작은 linear/square MLP를
기준으로 파이프라인을 확인하고, feature 수와 hidden width를 단계적으로 확장한다.

금융 도메인은 UCI credit-default를 사용해 비대칭 오류 비용과 불균형을 평가한다.
승인/거절의 중요성을 실제 임계값 및 false-negative/false-positive 비용으로
정의하되, 이를 실제 금융 의사결정 권고로 해석하지 않는다.

영상은 Fashion-MNIST의 공식 train/test를 이용해 MNIST 유사성에만 의존하는지를
확인한다. CNN-8/16, square MLP-64/128, 제한된 다항식 활성화를 비교한다.
ResNet/bootstrapping은 위 단계가 검증된 뒤 지원 범위로 추가한다.
큰 모델을 낮은 품질로 임의 변환해 암호화했다는 사실만으로 성공으로 계산하지 않는다.

## 비교 실험의 공정성

고정 고정밀도, 첫 실행 가능한 구성, 같은 B의 무작위/순차 탐색, 고정 절대오차 허용량,
입력별 마진 기준, 기존 compiler 출력+동일 gate, 전체 유한 비교 후보를 구분한다.
compilers의 native runtime이 다르면 원시 latency를 같은 수치로 합치지 않는다.
컴파일 산출 파라미터를 공통 evaluator에 넣는 실험은 native compiler 전체 성능과 구분한다.

목표 ε∈{0.01,0.001}, κ∈{0.90,0.95,0.99}, batch∈{1,16,128,512}를
개발용 자료에서 검토한 뒤 본 실험의 하나의 정책을 고정한다. 최종 감사 자료는 정책
선택 전에 봉인한다. 이 격자를 모두 검정한다면 사전에 family 크기를 계산해 보정한다.
가장 좋은 셀만 골라 독립된 단일 검정처럼 보고하지 않는다.

## 비용 측정

DP-03 첫 단계의 현재 근거는 [비용 구조 진단](dp03_cost_diag_v1_20260905/REPORT_KO.md)이다.
기존 문서에는 비용 모형과 후보 조건이 있었으나 별도 완료 protocol이나 수치 실행예산은
없었다. 새 `DP03_COST_DIAG_V1`에서 세 동결 Spambase linear 모델의 216개 비교 시행을
측정 전에 고정했다. 842행 조건의 두 단계 방식은 느렸고, 128행 조건의 관측 비용 감소는
정식 성능 우월성이 아니다. 모든 실제 호출의 키가 달라 기존 암호문 병합은 불가능하다.
다음은 인접 원배치 2개를 client의 같은 high key 문맥에서 묶는 최소 실험 하나만 제안한다.
실제 재포장·대기를 포함한 비교는 아직 수행하지 않았으며 후속 실험은 자동 시작하지 않는다.

설정·키 생성·calibration 비용과 요청당 실행 비용을 분리한 뒤,
배포 요청 수 H에 대해 총비용 C_setup+C_cal+H*C_request를 보고한다.
통신량은 public/evaluation key와 입력·출력 ciphertext를 분리한다.
메모리는 실제 peak RSS, latency는 cold/warm, batched/unbatched, queue waiting을 포함한다.
선택 횟수 감소를 시간 단축으로 치환하지 않는다.

정식 시간 비교는 기록된 실행 순서 무작위화와 paired 입력, 이상치 미삭제,
환경 유휴 확인, 사전 통계 단위를 요구한다. 파일럿의 병행 archive I/O와
새 키 생성이 포함된 시간은 기술적 관찰이며 성능 우월성 증명이 아니다.

## 논문 구조

1장: 실환경 결정 보존 문제와 기존 학회논문의 범위.
2장: CKKS·결정 마진·위험 제어·관련 compiler와 선택적 예측.
3장: 위협 모델·평문 기준·joint/selective 위험과 coverage·비용 문제.
4장: client gate, 구성/보정 분리, key-aware 위험 감사, 배치 정책.
5장: 공정한 대조군·보안/금융/영상·경계·분포 이동·독립 환경 실험.
6장: 증거 기반 주장, 실패 사례, 제한, 결론.

완성 기준은 “많은 모델에서 0회”가 아니다. 유효한 위험 주장, 유용한 반환율,
총비용의 개선 또는 명확한 비용 한계, 관련 연구와 구별되는 검증된 기여가 필요하다.
