# 검토 결정과 확대 행렬

최신 사용자 결정은 최종 PDF의 구성 선택 방법을 확대 검증하는 것이다. DeciProtect는 작업 공간·저장소 이름이며 별도 운영 시스템을 논문의 핵심으로 삼는 근거가 아니다. 이 문서는 실행 전 고정한 `protocols/FG_EXPAND_V1.json` 및 원시 입력 잠금과 연결된다. 전체 행렬을 한 번에 실행하는 계획이 아니다.

| 제안 | 결정 | 보강할 위치·새 정보·조건 |
|---|---|---|
| DP-03 queue/재계산 후속 | 현재 경로에서 제외 | 최종 PDF의 오프라인 구성 선택과 다른 목적. 기존 비용 진단·실패는 그 프로토콜의 결과로 보존. |
| Spambase 재사용 | 수정 후 실행 | 보안 응용, 57개 원특징의 자료에서 기존 train-only 최대 16특징 선택. DP 파일럿의 2-logit 모델/운영 gate는 이식하지 않고 원래 다항식·MLP4 출력 함수를 사용. 과거 노출 자료임을 명시. |
| HTRU2 | 실행 | 표형 중심 한계에 대해 원자료 규모·심한 불균형·8개 연속 특징을 추가. 기존 지원 연산 그대로 연결. 천문 자료이며 보안 적용의 직접 증거로 부르지 않음. |
| Wine 파일럿 | 자산 보존, 1차 실행 보류 | 178개로 별도 입력 확대에 부적합. 기존 전부 유보는 표본 부족에 따른 다른 운영 정책의 결과. 원래 구성 선택 실패라고 하지 않음. |
| MLP12 파일럿 재사용 | 결과 혼합 제외 | 기존 6개 모델 모두 최적화 200회 한도·미수렴. 이번 MLP4는 원래 고정 1200-epoch 학습을 사용하며, 이를 수렴 보증으로 표현하지 않음. |
| 기존 68 및 63 반복 | 중복 실행하지 않음 | 모델·분할·학습 seed와 원시 결과 목록을 먼저 확보. 단순 숫자 증가보다 새 자료와 별도 입력 평가 공백을 우선. |
| 초기 구성 별도 입력 평가 | 실행 | 기존 초기 탈락 21개는 별도 평가가 없었다. 신규 사례는 초기 구성도 별도 입력으로 평가하여 선택 입력 효과와 일반화 효과를 구분. |
| 최소 오차 선택 | 동일 유한 관측의 재분석 | 기존에도 수행됨. 새 CKKS 후보를 늘리지 않고 최대 관측 오차 최소 후보를 진단. 오차만 작으면 판정이 보존된다는 추론은 금지. |
| 외부 compiler 전부 설치 | 보류 | 문헌 조사와 실행 비교를 분리. 동일 그래프·평문 출력·파라미터 보안·timing 범위가 확인되어야 별도 protocol 작성. |
| 부트스트래핑·새 운영 위험 보장 | 제외 | 이번 목적이나 지원 연산 연결에 필요하지 않음. 기존 600회 상한을 신규 실행에 적용하지 않음. |
| 심사 점수 상향 | 제외 | 사례 수 증가나 테스트 통과로 점수·졸업 완성을 선언하지 않음. 과거 점수는 당시 모의심사 기록. |

## 실행한 첫 묶음의 사전 설계

| 데이터 | 원자료 / 중복 처리 후 | 모델 | 입력 분할 | 이 묶음이 추가하는 정보 |
|---|---|---|---|---|
| Spambase | 4,601 / 4,204; 57특징 | 기존 선형 본체+3차 출력부; 16→4 square→1 affine MLP | 학습 3,660, 개발 256, 선택 32, 별도 256 | 이메일 보안 자료에서 기준 전후 및 별도 입력 효과; 축소 마진에서 적용 영역 진단 |
| HTRU2 | 17,898 / 17,898; 8특징 | 같은 두 모델, MLP 입력 폭 8 | 학습 17,354, 개발 256, 선택 32, 별도 256 | 기존보다 큰 원자료, 약 9.2% 양성 불균형; 작은 마진의 빈도가 다른 경우 |

원자료 출처는 [UCI Spambase](https://archive.ics.uci.edu/dataset/94/spambase), [UCI HTRU2](https://archive.ics.uci.edu/dataset/372/htru2)이다. 실제 파일 크기·분포·중복 처리·원래 row ID는 각 `plaintext/*/manifest.json`에 기록했다. HTRU2의 9번째 열은 정답이며 입력 특징은 8개다. 동일 특징에 서로 다른 레이블이 있는 그룹은 통째로 제외하는 규칙을 두 자료에 동일 적용했다.

분할 seed 1701/2701/3701과 학습 seed 0은 최초 실행 전에 지정했다. 두 모델은 각 데이터의 같은 역할별 입력을 쓴다. 따라서 4개 사례는 4개의 학습 모델·4개의 데이터–모델 묶음이며, 4개 독립 데이터셋이 아니다. 별도 평가는 1,024 사례–입력 쌍이지만 데이터셋 내 모델끼리 같은 256행을 사용하므로 고유 별도 입력은 512개다. 새 키와 시간 반복은 이 수를 늘리지 않는다.

256개 별도 입력은 기존 WDBC 일부 사례의 113개보다 많지만 기존 모든 사례보다 많거나 전체 데이터 평가인 것은 아니다. 선택 32개는 비용 제한을 위한 사전 결정이며, 이 규모에서 얻은 선택의 일반화가 바로 검증 대상이다. 표형 스칼라 실행의 기존 비용과 현재 6-vCPU/16-GiB 환경을 근거로 45–150분, 새 자료 2GiB 이내, 단일 CKKS 프로세스로 제한했다. 시간 예산 상한은 180분이며 경계에서 남은 작업을 미실행으로 남긴다. 후보 수나 rho/delta를 유리하게 변경하지 않는다.

개발 자료에서 두 모델의 정답률·균형 정답률·AUROC·F1·마진을 기록하고, CKKS 결과로 모델을 고르지 않았다. 특히 Spambase MLP의 작은 마진은 보완 대상이지만 현재 입력/scale/임계값을 다시 맞추는 이유로 쓰지 않는다. 2개 개발 입력 연결 검사에서 그 사례의 적용 영역이 빈 것은 그대로 보존했다. 나머지 세 사례의 실제 암호화 연결 검사와 네 사례 모두의 Python–Go 평문 경로 비교로 연결을 확인했다. 구현 검증은 성능 향상·위험 보장이 아니다.

## 다음 단계용 후보 행렬 — 이번 실행 범위 밖

| 후보 | 원자료·입력 구상 | 모델·반복 축 | 얻을 정보 / 채택 전 조건 |
|---|---|---|---|
| 현재 두 자료의 고정 모델 별도 입력 확대 | 256 평가와 겹치지 않는 추가 입력은 새 split 전체 설계가 필요; 기존 학습 입력을 새 평가로 이동시키지 않음 | 같은 지원 구조; 분할 반복과 학습 seed 반복을 분리 | 선택 32개에 대한 의존·마진 층별 실패. 현재 실패를 보고 rho/delta나 특정 seed를 맞추지 않음. |
| Fashion-MNIST | 공식 60,000/10,000, 개발/선택은 train에서 분리, 별도 test 고정 1,000개부터 비용 검토 | 기존 다중 클래스 square MLP100·작은 LeNet; 사전 3학습 seed, 동일 split | 기존 MNIST 1개 고정 모델 및 이미 수행된 3-seed 분석에 더해 영상 분포 변화. 정확도·출력 의미·동점·경계 분모를 먼저 확인. |
| 모델 폭·깊이 | 새 두 자료, 동일 역할 분할을 후속 노출 자료로 명시 | 기존 MLP4 대비 폭 8/16 또는 기존 8→4 모델, 각 3seed | 깊이 자체는 이미 1/2/4/6/8 진단 있음. 새 정보는 학습된 모델의 마진·선택 비용과 깊이의 결합. 수렴/품질은 train/dev만 사용. |
| UCI credit default | 원자료 30,000행; 특징 유형·전처리 확인 후 선택/별도 개수 결정 | 기존 선형/MLP, 불균형과 더 많은 특징 | 새로운 금융 자료의 외적 범위. 범주형 처리가 평문 기준에 미치는 의미와 지원 차원을 먼저 고정. |
| IDS 자료 | UNSW-NB15 또는 CIC-IDS의 공식 분할·중복·시간/호스트 누수부터 확인 | 지원 선형/square MLP | Spambase가 침입 탐지 자료는 아니라는 공백. 다운로드 규모·레이블 의미·누수 해결 전 전체 실행 보류. |
| 독립 장비 | 기존 4개 모델·입력·선택 protocol 그대로 | 다른 물리 장비, 같은 파라미터/키 반복 정의 | 단일 VM 한계 직접 보강. 현재 VM의 코어/키 반복을 독립 환경으로 세지 않음. |

Fashion-MNIST·credit·IDS의 세부 예산은 실행용으로 고정한 사전 규격이 아니다. 출처·학습 품질·지원·실측 비용 확인 후 새 protocol로 고정할 후보이다. 표의 규모를 완료된 사례 수에 포함하지 않는다. 이번 묶음 종료 후 이 행렬을 자동 실행하지 않는다.

후속 후보의 원자료 확인 출처: [Fashion-MNIST 공식 저장소](https://github.com/zalandoresearch/fashion-mnist), [UCI credit default](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients), [UNSW-NB15 공식 페이지](https://research.unsw.edu.au/projects/unsw-nb15-dataset), [CIC-IDS2017 공식 페이지](https://www.unb.ca/cic/datasets/ids-2017.html). 이 자료들은 이번 묶음에 내려받거나 학습·암호화 실행한 자료가 아니다.

후속 후보의 비용 산정 상태: 새 split/폭·깊이 반복은 이번 측정의 사례별 wall/RSS를 출발점으로 삼되 모델 크기에 비례한다고 가정하지 않는다. Fashion-MNIST는 기존 다중 클래스의 500-slot 기록과 제안한 1,000입력의 packing/보안 조건을 먼저 대조해야 하므로 본 실행 예산은 아직 배정하지 않았다. Credit·IDS는 전처리·입력 차원·자료 크기가 고정되지 않아 수치 비용 추정을 보류했다. 독립 장비 반복은 해당 장비의 시간/메모리를 확인해야 한다. 이 미산정 후보들을 이번 사전 예산 안에 들어온 것으로 간주하거나 자동 실행하지 않는다.
