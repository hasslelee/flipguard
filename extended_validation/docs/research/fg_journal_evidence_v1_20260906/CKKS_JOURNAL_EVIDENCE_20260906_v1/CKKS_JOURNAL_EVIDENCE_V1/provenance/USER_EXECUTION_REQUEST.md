### 6.3 다중 클래스 경쟁 클래스 범위

PDF4쪽 식(4)의j범위와 Fig2의top-two 설명을 실제 최종 실험 검사 코드와 대조한다. 적용 영역을 정하는 마진과 수용검사의 경쟁 클래스 범위를 구분한다.

기존 검사에서 모든j≠k* 또는 동등한 최악 경쟁자를 검사한다면 이를 한 문장으로 명시한다. 새로운 수식이나 그림 재제작은 우선하지 않는다. 단순top-two검사만 있다면 모든클래스검사라고 설명만 바꾸지 말고, 관측 argmax 직접 검사와 충분조건의 주장 범위를 구분해 불일치를 보고한다. 구현 변경은 승인 범위가 아니다.

## 7. 비용 자료와 비교 기여의 보강을 분리한다

동결 지연 요약에서 다음을 찾아 실제 값을 제시한다.
- 1.00054의 기존95%신뢰구간 양끝과 집계·반복 단위.
- 사례/모델별 대표 절대 추론 시간과 초기/선택·적합기준/선택의 구분.

입력당 시간과 배치 시간,23,454대응시간비와 독립 표본 수를 혼동하지 않는다. 미측정 비용은 미측정으로 남긴다. 기존 통계 결과의 설명 보강을 위해 CKKS시간실험을 새로 하지 않는다.

이미 완료한 후속 A/B/C와 실제 외부 비교는 재실행하지 않는다. PDF한정 심사의 ‘강한 비교 필요’는 심사 당시 본문에 없다는 뜻이지, 저장소에 그런 실험이 전혀 없다는 뜻이 아니다.

비교 기여 자료는 별도 표로 정리한다.
- 원래 PDF에 실제로 들어 있는 내부제거·유한집합·외부보조관측.
- 완료한 후속 비교가 어떤 질문을 검증했고 무엇이 미관측이었는지.
- 최종 논문 방법과 다른 변형·기준·환경을 사용한 부분.
- 새 확장 주장에 쓸 수 있는 근거와 쓸 수 없는 해석.

후속자료를 본문에 자동 삽입하지 않고, 통합한다면 어느 절의 어떤 주장을 보완/제한해야 하는지 초안을 남긴다. 긍정결과만 선별하지 않는다. 같은 방법을 일반화하는 새로운 원고에서는 이미 확인한 실패와 무차이를 숨기지 않는다.

관련 연구의 실제 선택/오차 조건 설명은 이미 확인한 원문 및 정정 기록을 재사용한다. 외부 기능을 추가로 단정해야 하는 항목만 정확한 판본 원문으로 확인한다. 전문이 없으면 미확인으로 둔다. 전수 최신문헌 조사나 모든compiler설치를 이번 작업에 추가하지 않는다. FHE-Agent의 정정 전 설명을 다시 쓰지 않는다.

## 8. 후속 정책 자료는 확보 완료로 처리한다

`POLICY_CONTEXT_KO.md`와 정책 소스는 이미 확보돼 있다. 사용자에게 다시 첨부하거나 코드를 찾아 달라고 요구하지 않는다. 정책 도입 경위·비활성 이유를 찾기 위한 전체 archive 탐색도 반복하지 않는다.

C′는 초기 backend 유효 최소 구성 뒤, 첫 암호화 평가 전에 같은 logN에서 scale 여유를 쓰는 별도 변형 후보다. 원래 C나 PDF에 이미 실행된 방법으로 넣지 않는다. 코드의 직접 등급 판정이 logN 동일성이라는 점과 실제 지연 동일성은 구분한다. 아직 실행되지 않은 S33을 선택 결과로 부르지 않는다.

C′ 활성화, 새 정적 파라미터 생성, CKKS 실행, 예약 684개 접근은 이번 범위 밖이다. 이번 논문 보강의 실행 완료를 후속 정책 실험 승인으로 해석하지 않는다.

후속 Bank 코드의 구체 소수 보안 검사 호출 미확인과 기존 사후 검증 기록은 서로 다른 근거일 수 있다. 원고의 보안 설명을 채우는 과정에서 문제가 된다면 수행 시점과 기록을 분리해 짧게 정리한다. 확인하지 않은 현재 실행을 과거 검증으로 표현하거나 검사 함수 미호출만으로 보안 위반을 단정하지 않는다. 이 문제를 새 보안 연구로 확대하지 않는다.

## 9. 실제 산출물과 완료 조건

새 작업 폴더를 만들되 이미 있는 경로면 덮어쓰지 않는다. 권장 이름은 `docs/research/fg_journal_evidence_v1_20260906/`이며 충돌 시 새 run suffix를 사용한다.

최종 산출물:

1. `MANUSCRIPT_PATCH_KO.md`: 최종 PDF의 쪽·절·앞문장·대상문장·뒤문장과 연결한 최소 교체/삽입 문안. ‘보강 필요’만 쓰지 말고 확인된 값이 들어간 실제 문단·표를 제공한다.
2. `REPRODUCTION_SUPPLEMENT_KO.md`: 합성 예시·537 생성 규칙·실제 재현 자료 및 명령·데이터/모델/분할 설명. 코드 식별자와 본문 용어를 구분한다.
3. `evidence_tables/`: 기존 자료로 채운 후보 명세·모델 품질·사례 분모·추가 분석 분해·시간 요약. CSV 또는 Markdown이면 충분하며 불필요한 새 그림/PPTX를 만들지 않는다.
4. `CLAIM_STATUS_AND_GAPS_KO.md`: 보강 완료한 항목, 자료 부재, 모순, 기여상 미확인, 별도 방법 변경 문제를 구분한다. 과거 심사 점수를 재활용하지 않는다.
5. 출처 manifest와 재집계 검증 기록, 위 실제 파일을 담은 소규모 ZIP.

원고 패치는 장절·기본 용어·설명 수준을 유지하고 본문 수식과 의사코드를 자동 복원하지 않는다. 전체 원고를 갈아엎는 재작성본 대신 작은 삽입 단위로 제공한다. 부록과 본문 내용을 동일하게 대량 중복하지 않는다.

모든 새 숫자는 원시/기존 집계·필드·계산 규칙에 연결한다. 실행하지 않은 측정이나 추정값을 채워 넣지 않는다. 후보 평가89/537, 주요68, 적용 입력 총계 등 기존 핵심 수치와 불일치하면 자동 수정하지 않고 별도 불일치 기록을 남긴다.

CRC/manifest 검증은 새 산출물 묶음 범위에서만 수행한다. 이전72파일 ZIP이나 전체 archive를 다시 확대 패키징하지 않는다. 예약 감사 실제 행·점수·키·토큰·가상환경·font 파일을 포함하지 않는다.

최종 응답은 추가한 문서 수나 해시만 강조하지 말고 다음에 답한다.

- 최종 논문의 어느 공백을 실제 값과 문장으로 채웠는가?
- 어떤 문장은 범위나 표현을 수정해야 하는가?
- 기존 방법을 바꾸지 않고 해결한 것과 아직 기여 증거가 부족한 것은 무엇인가?
- 남은 결정 중 새 실험이 정말 필요한 것은 무엇인가? 이미 한 비교를 또 요청하지 않는다.

실제 파일을 첨부하거나 정확한 생성 경로를 제시한 뒤 종료한다. 최종 PDF 자동 수정·새 방법 활성화·새 암호화 실험·push로 자동 이어가지 않는다.
