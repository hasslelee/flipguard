## 0. 이번 지시의 목적과 실행 승인 범위

정보보호학회논문지 원고 작업은 완료로 둔다. 그 원고는 FlipGuard의 연구 결과를 정리한 보존 기준이다. 이번 작업은 `/home/ckks2/deciprotect`에서 같은 연구를 석사학위논문으로 완성하기 위한 제한된 추가 검증이다.

연구 주제는 **평문·암호화 추론 간 판정 일관성을 위한 CKKS 실행 구성 선택**이다. 입력은 고정된 모델의 계산 그래프·판정 규칙·선택용 자료이고, 출력은 수용 조건을 만족한 실행 구성 또는 상한 내 미선택이다. 오프라인 선택 → 구성 확정 → 별도 입력 평가라는 중심을 바꾸지 않는다.

이 지시문을 사용자가 실행 지시로 전달한 경우, 아래 범위의 구현·테스트·실제 CKKS 실행·분석·학위논문 초안 작성을 승인한 것으로 처리한다. 과거의 ‘다음 실험 자동 착수 금지’ 때문에 같은 실행 승인을 반복해서 묻지 않는다. 단, 이번 유한 묶음 밖으로 확대하지 않는다.

이번에 허용한 핵심 변경은 **기존 비활성 정밀도 여유 옵션을 별도 C′ 실험 경로로 연결하는 것 하나**다. 기존 C는 그대로 둔다. rho·delta·선택 입력 수의 변화는 기존 기법의 민감도 실험으로 식별하며 C′와 동시에 섞어 최종 정책을 만들지 않는다. 추가 데이터 연결과 이미 지원하는 모델의 폭 확대는 평가 범위의 확장이다.

다음은 승인하지 않는다: 운영 중 재계산·유보·큐 시스템, 새 위험 제어 체계, 새로운 CKKS/부트스트래핑 구현, 외부 컴파일러 개발, 새 학습형 튜너, 비용 등급 하향 탐색이나 앙상블 선택 알고리즘, 유료 자원 구매, 자동 외부 업로드·push. 주제·보안 가정·평문 모델 의미를 바꿀 필요가 있으면 관련 작업만 멈추고 근거와 최소안을 보고한다.

이번 실행의 종료 목적은 ‘모든 비교에서 이길 때까지 연구’가 아니다. 핵심 미확인 가설을 한 번의 제한된 실험으로 검토한 뒤, 채택 여부를 결정하고 학위논문 집필로 전환한다.

## 2. 연구 질문과 주장 범위를 고정한다

확인할 질문은 세 가지다.

1. 현재 선택 기준은 어느 마진·오차·선택 입력 조건에서 판정과 오차 여유를 유지하며, 어느 조건에서 실패하거나 적용 범위가 좁아지는가?
2. 같은 큰 계산 구조를 유지하면서 정밀도 여유를 사용하는 C′는 기존 C를 실질적으로 보강하는가? 이미 성공한 B30과 비교하면 얻는 이점과 비용은 무엇인가?
3. 기존 모델 범위와 새로운 침입 탐지 사례에서도 같은 오프라인 선택 절차를 사용할 수 있는가?

‘보장’은 주장 대상·전제·범위를 명시한다. 기존 이진/다중 클래스 충분조건이 해당 입력·실행에서 성립하면 판정이 유지된다는 사실과, 유한한 선택/별도 입력에서 통과했다는 관측은 구분한다. 후자를 모든 미래 입력·키의 무조건 보장으로 바꾸지 않는다. 이 구분을 위해 실시간 gate나 새로운 통계 보장 시스템을 개발하지 않는다.

성공의 기준은 판정 보호와 그 비용이다. 평문 정답률 향상, 암호학적 기밀성의 신규 증명, 악의적 서버의 무결성은 이번 기여로 추가하지 않는다. 다만 모델 품질과 보안 파라미터 적합성은 실험 전제로 확인한다.

이미 확인한 무차이·불리한 결과도 유지한다. A30/B30의 동일 선택, 같은 수치 요구를 충족하지 않은 C의 비용 절감, Fashion seed0의 큰 비용, Bank 적용 영역 실패를 삭제하지 않는다. 이를 모두 평균내어 ‘전반적으로 무손해’로 표현하지 않는다.

## 3. 작업 A: 설정값·적용 범위·선택 입력 수의 영향

### A1. 기존 출력의 재분석 — 새 CKKS 없이 먼저 수행

현재 rho=0.5, delta=0.001, B=4의 결과를 기준점으로 보존한다. 아래는 최적값을 찾기 위한 튜닝이 아니라 결과가 설정에 얼마나 의존하는지 보는 제안 격자다.

- rho: 0.25 / 0.5 / 0.75, delta는 0.001로 고정.
- delta: 0 / 0.0001 / 0.001 / 0.01, rho는 0.5로 고정.
- 두 축을 곱한 전 조합은 실행하지 않는다. 기준점을 공유한 6가지 설정이다.

표형 4모델, Fashion 3모델, 외부 Bank의 기존 원시 출력에서 설정별 전체/적용/경계 수, 판정 불일치, 오차 조건 위반, 마진 대비 오차 비율을 재집계한다. 접근 가능한 기존 주요 사례의 같은 자료가 있으면 읽기 전용 집계에 함께 쓸 수 있지만, 이를 위해 archive 전수 추출을 하지 않는다.

delta=0도 평문 동점은 제외되므로 ‘모든 입력 보장’이 아니다. rho를 바꿀 때 판정 불일치 자체는 고정 출력에서 달라지지 않는다. delta를 키워 실패 입력이 분모 밖으로 이동한 것을 보호 개선으로 세지 않는다.

각 설정의 고유 적용 영역뿐 아니라, 같은 입력 집합에서의 판정 결과와 적용 비율을 함께 표시한다. 전체 입력 분모를 버리지 않는다. 출력 척도·정규화·임곗값은 원래 모델대로 고정한다. 다른 모델에 같은 절대 delta가 동등한 난이도를 의미한다고 가정하지 않는다.

이 재분석은 **이미 고정된 구성의 수용 조건을 다시 판정한 것**이다. 그 설정으로 새롭게 구성을 선택했거나 새로운 독립 감사에 통과했다고 보고하지 않는다. 공개된 오류 예산 포함 관계도 새 효과로 재발견했다고 하지 않는다.

### A2. 실제 재선택이 필요한 최소 민감도 비교

민감도 설정이 초기 합성과 조정에 미치는 영향은 재분석만으로 대신할 수 없다. 기존 자산의 Spambase 선형+3차, Spambase MLP, Fashion seed0을 대표 대상으로 한다. 이는 효과가 좋았던 경우만의 표본이 아니라, 초기 조정·좁은 적용 영역·비용 등급 상승이라는 서로 다른 알려진 상황의 진단 사례다.

A1과 같은 6개 설정의 실제 C 선택을 수행하되 선택 입력·가중치·보안 기준·상한4·3키를 고정한다. 모델과 선택 결과를 바꿔가며 유리한 설정 하나를 고르지 않는다. 자원 예측상 18개 선택 작업이 예산을 넘으면 CKKS 결과를 보기 전에 모든 사례에 공통으로 적용할 축소 격자를 protocol에 정한다. 기준과 불리한 방향을 함께 남긴다.

서로 다른 설정에서 최종 literal과 경로가 같으면, 같은 모델·입력·키 정책의 고정 구성 감사는 공유할 수 있다. 동일 후보를 설정 수만큼 독립 표본으로 늘리지 않는다. 실제 선택 비용은 각 실행의 비용으로 기록한다.

### A3. 선택 입력 수는 두 기존 모델에서만 비교

Spambase 선형+3차와 HTRU2 MLP를 우선 대상으로, 이미 고정된 학습 모델의 개발/선택 후보 풀에서 16 / 64 / 256개를 사용하는 비교를 검토한다. 이 수는 제안값이며 실제 사용 가능한 후보 풀과 중복을 확인한 뒤 본 실행 전에 확정한다. 부족한 수를 채우려고 학습·시험 역할을 조용히 섞지 않는다.

가중치·전처리·출력 정규화·rho·delta를 고정한다. 공개한 해시/난수 순서 3개에 따라 중첩 부분집합을 만들고, 모든 크기를 같은 규칙으로 추출한다. 키 블록과 입력 추출 seed를 별도로 기록한다. 작은 마진만 골라 넣는 새 선택 정책이나 사분위 정책은 함께 넣지 않는다.

최종 감사 입력은 이 풀과 분리된 기존 평가 자료를 사용하고, 이미 본 자료의 재평가임을 명시한다. 새 구성은 반드시 선택용 입력만으로 확정한다. C′ 또는 예약 감사684개는 이 작업에 사용하지 않는다.

관측할 것은 선택 성공률, 선택된 scale/N/Q/P, 실제 구성 평가 수·정적 시도 수·총 선택 비용, 별도 입력 판정/오차 위반 및 적용 비율이다. 입력 수가 많아도 같은 구성을 선택하면 그 결과를 남긴다. 새로 많은 모델을 학습하지 않는다.

B=1/2/4는 기존 순차 선택 궤적의 접두 구간으로 정확하게 계산할 수 있는 부분부터 재사용한다. 예산이 후보 순서에 영향을 주는 코드라면 접두 재해석을 실제 B별 실행으로 부르지 않는다. B=4에서 멈춘 자료를 B=8의 결과로 외삽하지 않는다.

## 4. 작업 B: C′ 최소 보완의 실제 검증 — 이번에 제한적으로 실행

### B1. 변경은 옵션 하나이며, C는 보존

기존 `maximize_within_min_log_n` / `maximizePrecisionWithinMinLogNTier`를 확인하고 별도 variant/명령에 연결한다. 같은 정책을 새로 발명했다고 쓰지 않는다. 기존 함수의 도입·비활성 이유는 미기록이므로 추측하지 않는다.

확인된 정책 위치는 최초 백엔드 유효 구성을 얻은 뒤, 첫 암호화 평가 전이다. 최초 수용 뒤의 후처리로 바꾸지 않는다. 실패 후 RepairCandidate의 기존 규칙·상한은 유지한다.

기존 함수는 logN 동일성을 직접 검사한다. 이번 실험에서는 동일 contract에서 Q/P 개수·packing·회전·요구 레벨·실행 경로가 실제 유지됐는지도 검사한다. 같은 N이라는 이유만으로 같은 측정 비용이라고 가정하지 않는다. 유지돼야 할 구조가 달라지면 새 알고리즘으로 몰래 보완하지 말고 그 변형을 부적격으로 기록한다.

새로 생성한 실제 소수와 scale, 선언/실제 Q·QP 크기, 적용한 분포·보안 한도·Lattigo 유효성 결과를 연결한다. 단순 유효성 검사를 개별 공격 비용 추정으로 표현하지 않는다. 기존 128비트 목표의 보안 정책을 완화하지 않는다.

### B2. 대상과 대조군

정적 구성 생성은 기존 7모델과 Bank에서 확인할 수 있다. 실제 비교는 우선 **Bank, Spambase MLP, Fashion seed0의 3모델**로 제한한다. Bank는 알려진 실패, Spambase MLP는 작은 N의 비용 이득과 낮은 적용 범위, Fashion seed0은 이 옵션이 큰 N 선택 문제를 해결하지 못하는 음성 대조다. 개선이 안 나올 것으로 보여도 사전 범위에서 제외하지 않는다.

각 모델에서 C, C′, B30을 같은 원래 선택 입력·rho·delta·3키·최대4회로 평가한다. 선택용 키 블록 2개를 기준으로 하되, 이미 완료한 동일 실행은 과거 결과로 재사용하고 새 비교의 키/시간 관측과 혼합하지 않는다. 새 대응 시간은 두 방법을 모두 같은 시기에 측정한다.

B30은 마진을 쓰지 않는 독립 후보 생성과 기존 판정 수용 검사를 유지한다. C′를 B보다 유리하게 보이게 하려고 B30의 시작점·후보 순서·정확성 기준을 바꾸지 않는다.

정밀도 여유 규칙이 C 전용이 아니라는 점도 평가한다. 같은 구조적 규칙을 마진 없이 B의 산출 구성에 적용한 B30+slack을 정적 보조 비교로 생성할 수 있으면 확인한다. C의 마진 유래 WorkloadContract를 B 생성기에 전달하지 않는다. 구현이 단순 연결로 가능하고 독립성이 유지되며 유효한 구성이 다르면 4번째 보조군으로 포함한다. 불가능하면 이유를 밝히고 C′의 독점적 가치 주장을 하지 않는다. 이 부분 때문에 핵심 3군 비교를 무기한 지연하지 않는다.

동일 모델에서 방법별 최종 전체 literal·실행 경로가 같으면 감사 결과를 공유하고 alias를 표시한다. 정적 시도, 암호화 후보 평가, 키 문맥, 입력–키 관측은 각각 별도 단위다.

### B3. 데이터 사용과 예약 감사684개

C′ 규칙은 기존 보고서에 제안한 옵션 그대로 고정한다. Bank의 원래 선택16개를 세 주 비교군에 동일하게 사용한다. 과거 실패 입력을 선택에 추가하거나 입력 층화·rho/delta 변경을 섞지 않는다.

**이번 실행 승인에는, 아래 조건을 모두 충족한 뒤 Bank 예약 감사684개를 한 번의 최종 비교에 사용하는 것이 포함된다.** 감사 데이터에서 좋게 나오는 정책을 고르는 승인은 아니다.

기존 Bank 스트레스16개는 이미 노출된 회귀 점검으로 별도 실행한다. 새684개와 합쳐 하나의 일반 오류율을 만들지 않는다. 원래 일반 감사32개도 비교 이력으로 구분한다.

Spambase MLP는 기존 별도 입력256개 전체를, Fashion seed0은 공식 시험의 사전 지정 부분집합을 사용한다. Fashion 감사 규모는 기존 입력별 정답/마진/오류를 선택 기준으로 삼지 않고, 개발용 실행비용과 가용 예산으로 1,000개 또는 전체10,000개 중 본 실행 전에 고정한다. 다른 방법에 같은 입력을 적용한다. 미사용 감사인 척하지 않는다.

### B4. 채택과 비채택

C′의 결과는 아래처럼 분류한다.

- C보다 판정/오차 위반이 줄고 비용이 유지되지만 B와 같으면: 기존 기법의 제한적인 신뢰성 보강.
- 같은 판정 목적·공통 적용 범위에서 B보다 선택 또는 추론 비용이 줄면: 해당 조건의 추가 효율 근거. 더 엄격한 수치 목표도 같은지 별도로 표시.
- 판정은 모두 같고 오차만 작아지면: 수치 여유 개선. 판정 오류 감소라고 쓰지 않음.
- C′가 큰 비용 증가·새 위반·구조 변경을 일으키거나 실제 이득이 없으면: 채택하지 않음 또는 제한적 옵션으로만 보존.

비용 변동 범위와 상대/절대 증가를 같이 보여준다. 결과를 본 뒤 임의의 ‘5%면 무손해’ 같은 합격선을 만들지 않는다. 필요하면 실험 전에 정한 실무적 허용치를 별도 정책값으로 쓰되 수학적 보장처럼 다루지 않는다.

이 옵션은 이미 선택한 큰 N을 작은 N으로 줄이지 않는다. Fashion seed0의 약2배 비용을 이 옵션이 해결해야만 성공이라고 정하지 않으며, 해결되지 않은 비용 한계는 그대로 보고한다. 결과에 맞춘 N 하향 탐색이나 C″를 이번에 추가하지 않는다.

## 5. 작업 C: 새로운 자료는 침입 탐지 한 묶음까지만

이 작업은 데이터 이름 늘리기가 아니라 보안 응용 자료와 표형 모델 폭의 보강이다. A/B 작업과 별개로, 출처·구현·자원 조건을 만족하면 이번 승인 범위에서 실행한다. C′가 이겨야만 새로운 자료를 평가한다는 조건을 두지 않는다.

우선 후보는 **UNSW-NB15의 공개된 정형 특징 자료**다. 공식 설명의 training175,341 / testing82,332 분할과 실제 제공 파일을 먼저 대조한다. 출처: `https://research.unsw.edu.au/projects/unsw-nb15-dataset`.

대규모 PCAP 수집·파서 개발은 하지 않는다. 공식 특징 CSV를 사용할 수 없거나 데이터 의미를 검증할 수 없다면 이 작업을 보류하고 이유를 보고한다. 임의의 Kaggle 재가공본으로 조용히 바꾸지 않는다. UNSW는 통제된 환경의 생성 자료이므로 실제 서비스에서의 전향적 검증으로 부르지 않는다.

평가는 정상/공격 이진 판정으로 제한한다. 이미 지원하는 선형+다항식 계열과 제곱 MLP 한 계열을 쓰고, MLP 은닉 폭32를 우선 검토한다. 기존 hidden4보다 넓은 계산 요구를 확인하는 목적이며 최첨단 대형 모델 실험으로 표현하지 않는다. 학습 초기값0/1/2의 최대6개 모델이다. 구조·학습 규칙은 개발 자료로 정하고 최종 평가 후 좋은 seed만 남기지 않는다.

공식 학습 자료 안에서 학습·개발·구성 선택 후보를 분리한다. 시험 자료는 모델 선택·정규화·특징 선택·출력 스케일 결정에 쓰지 않는다. ID와 정답·공격 유형을 예측 특징에 넣지 않는다. 범주 인코딩과 결측/비정상 처리도 학습 자료로 고정한다. 공식 자료 설명의 특징 개수를 실제 모델 입력 차원으로 그대로 적지 말고 제거·인코딩 후 차원을 기록한다.

중복과 식별자 누수를 점검하고, 공식 분할을 시간/호스트 분리라고 주장하지 않는다. 시간·세션 metadata를 직접 확인하지 못했다면 랜덤/공식 분할의 결과라는 범위를 유지한다.

평문 모델의 품질은 accuracy뿐 아니라 balanced accuracy, 공격 클래스 recall/F1 등을 보조적으로 확인한다. 오분류를 고치는 연구로 바꾸지 않는다. 구현 오류·비정상 학습과 실제 품질 한계를 구분하고 후자를 숨기지 않는다.

구성 선택 입력은64 또는128개, 별도 CKKS 감사는 시험자료의 고정2,048개를 시작 제안으로 둔다. 개발용 실행비용과 클래스 분포를 보고 본 평가 전에 확정한다. 표본을 바꾸기 위해 시험 score/마진/CKKS 결과를 보지 않는다. 82,332개 중2,048개만 실제 평가했다면 두 수를 구별하고, 작은 마진·평문 오분류 입력을 지우지 않는다.

본 비교는 원래 C와 독립 수치 A30·단순 판정 B30을 기본으로 한다. A/B 포함 관계를 확인하여 무차이가 예정되는 조건을 해석한다. C′는 A/B 작업에서 선택한 변형을 시험 결과에 맞춰 고르는 방식이 아니라, IDS 본 평가 전에 규칙을 확정한 별도 보조군으로만 넣을 수 있다. 후보 범위를 부풀려 감소율을 높이지 않는다.

선택된 서로 다른 구성의 감사와 대표 대응 시간만 실행한다. 모든 후보×모든 시험행×모든 seed×모든 민감도 조합으로 확대하지 않는다. 세 seed가 같은 평가 입력을 쓸 때 고유 입력과 사례–입력·키 관측을 구별한다.

네트워크 전체 배포, 새 실시간 서비스, 입력 이동 후 자동 재튜닝을 추가하지 않는다. 새 데이터1개·두 모델계열·최대6학습모델을 마치면 이 데이터 확대 작업은 종료한다.

## 6. 환경·비용·반복의 보강

같은 판정 목적에서 비교할 때 선택 전체 시간, 준비/키 생성, PDF 정의의 추론, peak memory, 직렬화한 암호문·평가키 크기를 구분한다. 실제로 측정하지 않은 통신·서비스 대기는 0이 아니라 미측정으로 둔다. 전체 선택비용과 반복 추론의 비용 절충은 기존 값으로 계산 가능한 범위에서만 분석한다.

시간 비교는 동일 모델·입력·packing·자원·준비 비용 기준을 맞춘다. 예열과 순서 교대, 키별 반복값을 보존하고 이상치를 임의로 지우지 않는다. 최소한 중앙값/범위·키 블록별 비율·절대 시간을 보인다. 단순 표준편차를 독립 입력의 위험 상한으로 바꾸지 않는다.

학회 투고본에서 신뢰구간을 삭제한 것은 문서 편집 결정이다. 이번 연구의 원시 반복 기록·불확실성을 삭제하라는 뜻이 아니다. 새로운 학위논문에 필요한 통계 설명은 반복 단위에 맞춰 짧게 제안하되, 단어만 늘리거나 기존 학회 원고를 고치지 않는다. 형식적인 유의성 통과를 연구 완료 조건으로 만들지 않는다.

이미 접근 권한이 제공된 별도의 물리 장비가 있으면, 대표적인 표형1·다중클래스1·회전경로1을 선정해 새 키의 실제 CKKS 선택/감사와 대응 시간을 제한적으로 재실행한다. 원시 CSV 재집계나 같은 호스트의 새 컨테이너를 독립 장비 검증이라고 하지 않는다. 새 장비가 없으면 실행 묶음만 준비하고 미실시로 기록한다. 유료 서버를 주문하거나 자격증명을 요청하는 일을 자동화하지 않는다. 장비 미확보 때문에 학위논문 집필을 무기한 멈추지 않는다.

## 7. 실행량은 유한하게 관리하라

작업A·B·C의 전체 후보/키/입력/배치별 실행 행렬을 작은 machine-readable protocol로 먼저 고정한다. 완벽한 새 관리 프레임워크를 만드는 대신 기존 runner·verifier·명세 형식을 사용한다.

첫 연구 재개 묶음의 새 CKKS/native 실행 누적 경과시간 상한은 **24시간**으로 제안한다. 이는 예상 완료시간·통계적 합격선이 아니라 자원 사용 상한이다. 기존 실측으로 예상치를 먼저 계산하고, 예산을 넘을 것으로 보이면 CKKS 본 결과를 보기 전에 공통 입력 수·반복·보조군 범위를 줄여 기록한다. 계획 축소가 연구 질문을 무의미하게 만들면 해당 작업은 보류한다.

현재 가용 메모리와 디스크를 확인하고 OOM/디스크 고갈을 피할 실제 한도를 정한다. 수치 성공 여부가 아니라 자원 상태에 따른 안전 중단은 허용하되 중단 기록을 유지한다. 선택 상한B=4와 전체 연구 실행 상한을 혼동하지 않는다.

작업 우선순위는 A의 기존자료/민감도 → B의 제한된 C′ 비교 → C의 응용 사례다. 학위논문 작성은 준비된 장부터 병행한다. 일부 실험이 실패/미지원/예산초과여도 기존 자료로 쓸 수 있는 장은 완성한다. 반복해서 ‘다음 한 건’을 자동 예약하거나 상한을 늘리지 않는다.

C′가 기존 C와 같은 구성을 내거나 연구 효과가 미관측이더라도 정한 작업은 결과로 마감한다. 반대로 실행 오류 때문에 비교 자체가 성립하지 않았으면 ‘추가 가치 없음’이 아니라 ‘판단 불가’로 표시한다.

## 8. 학위논문은 지금부터 별도 원고로 작성한다

이번 작업 종료 때 단순 로드맵만 제출하지 않는다. 이미 확정된 내용으로 실제 문장·표가 들어간 학위논문 초안을 작성한다. 학교 고유 양식이 아직 없으면 MD/TXT 구조화 초안으로 시작하며 학회 PDF를 늘려 쓰거나 임의 학교 서식을 만들지 않는다.

권장 장 구성:

1장 문제와 연구 목적: 판정 일관성, 학회 연구와 학위 확장 범위.
2장 배경과 관련 연구: CKKS, 판정 마진, 수치 기준/구성 선택/불일치 검사 연구의 관계.
3장 문제 정의와 선택 조건: 입력·출력·범위·조건부 충분조건·미선택의 의미.
4장 제안 선택 절차: 기존 C를 중심으로 설명하고 C′는 실제 검증·채택된 경우에만 별도 절로 구분.
5장 평가 설계와 결과: 기존 주요/추가, 데이터 확대, A/B/C, 민감도, C′ 및 응용 검증을 프로토콜별로 연결.
6장 논의와 결론: 언제 조건이 도움이 되고 언제 수치 기준으로도 충분한지, 보호 범위·비용·실패·환경 한계.

기존 학회 연구에서 이어받은 내용과 새 분석·실험을 구별한다. 게재/출판 여부는 실제 상태로 적고, 학회 원고가 완료됐다는 이유로 게재 확정이라고 쓰지 않는다. 적용 범위에서의 0회, 경계 위반, 별도 오차 위반, C의 비용 손해를 함께 남긴다.

결론에 아직 하지 않은 실험의 예상 결과를 넣지 않는다. 남은 실행 구간만 ‘미완료’로 표시하고, 이미 완료된 배경·방법·기존 평가 장을 자리표시자로 비워 두지 않는다.

문체는 사용자 공통 맥락을 따른다. 쉬운 한국어 논문체, 필요한 수식만 사용하고 내부 버전명·hash·상태 코드가 본문을 지배하지 않게 한다. 재현 기록은 실행 자료에 유지하되 본문에 관리용 문구를 되살리지 않는다. 삭제한 Algorithm·수식을 학위논문이라는 이유로 자동 복구하지 않는다.

문헌은 기존 검토와 정정을 재사용하고 실제 쟁점만 보강한다. HEDiff는 판정 이탈 탐색, ELASM은 오차/비용, Orion·FHE-Agent는 실행 구성과 평가 범위의 비교 대상으로 구분한다. 선행연구가 판정을 전혀 보지 않았다는 포괄적 주장을 만들지 않는다. 정확한 출판 상태·판본은 원문으로 확인하고 최신 날짜만을 신규성 근거로 삼지 않는다. 대규모 외부 도구 재구현을 요구하지 않는다.

## 9. 완료 판정과 제출물

연구상 완료 기준은 다음과 같다. 이는 학교 학위 심사의 통과 보증이나 모든 기존 방법 대비 승리 기준이 아니다.

- 기존 기법의 내부 판정 보호 효과·선택 품질·적용 한계를 설명할 수 있다.
- rho/delta/선택 자료에 의존하는 범위가 드러나고 결과를 사후 미화하지 않는다.
- 최소 변형 C′는 이번 제한된 비교로 채택·제한적 채택·비채택·판단 불가 중 하나로 정리된다.
- 응용/모델 폭과 독립 환경의 실제 수행 범위가 표시된다. 미완료이면 주장 범위를 축소해 남긴다.
- 학회와 후속 프로토콜의 결과를 혼합하지 않고 학위논문에 연결할 수 있다.

다섯 조건을 충족하면 ‘석사학위논문 본격 집필로 전환’이라고 보고한다. 차별적 개선이 약하다고 해서 무조건 추가 데이터·새 알고리즘을 시작하지 않는다. 학위 원고로 정리할 가치와 강한 국제적 신규성의 성립 여부는 별도로 평가한다. 최종 학위 판단은 지도교수·학위위원회의 범위다.

필수 제출물은 다음과 같다. 기존 유사 파일이 있으면 갱신/재사용하며 보고서 수를 불필요하게 늘리지 않는다.

- `THESIS_STATUS_AND_SCOPE_KO.md`: 현재 근거, 실제 신규 실험, 종료/남은 사항을 한눈에 표시.
- `THESIS_EXPERIMENTS_KO.md` 및 표/원시 인덱스: A/B/C 작업의 실제 결과와 단위·비용·실패.
- `CPRIME_DECISION_KO.md`: 기존 C와의 차이, 대조군 대비 이점·한계, 채택 여부. C′ 미실행이면 사유와 미확인을 명시.
- `THESIS_DRAFT_KO.md` / `.txt`: 실제 본문 초안, 기존 결과와 새 결과의 대응.
- 사용한 protocol, 코드 diff, 실행 명령, 데이터/모델/구성 식별자, 검증 결과와 필요한 그림.
- ChatGPT가 열 수 있는 실제 제출 ZIP. 원시 전체·archive·가상환경·비밀키·토큰은 넣지 않는다.

원본 FlipGuard, 기존 논문·결과와 완료 보고서는 덮어쓰지 않는다. 정책 변경은 격리된 실험 경로와 명시적 ID로만 수행한다. 보존을 이유로 전체45GB를 다시 검사하거나 Git 이력을 정리하지 않는다. 결과물 경로만 보고하지 말고 검토에 필요한 실제 문서·표·소스 변경분을 전달한다.

최종 응답은 ‘테스트 몇 개 통과’보다 먼저 **현재 주제에서 무엇을 더 알게 됐고, 어떤 변형을 채택하며, 이제 학위논문 작성으로 넘어갈 수 있는지**를 답한다. 이번 묶음을 마치면 자동 후속 실험을 시작하지 않고 종료한다.
