# Step 7G.8: Research-Core Readiness Gate

## Purpose

Separate completion of the scoped empirical systems study from admission of
paper claims. The gate is static: it runs no CKKS workload and changes no
frozen policy or evidence.

## Scoped Core

The evaluated core is:

> Empirical finite-set decision-integrity admission for declared CKKS graph
> adapters, bounded failure-aware direct synthesis, abstention, Security V2
> filtering, and no-retuning locked replay.

The gate requires verified support, at the state already declared in
checkpoint V5, for direct synthesis, bounded repair, finite decision
certification, trial reduction, Security V2 bounded-catalog comparison,
paired latency, security, locked audit, training-seed extension, structural
adapters, and artifact reproducibility.

`PARTIALLY_SUPPORTED` is acceptable only where the limitation is intrinsic to
the declared scoped core and is explicitly retained.

## Excluded Claims

The following do not block completion of the scoped core because they must be
excluded rather than weakened into the paper:

- a natural-data decision-margin effect on synthesized parameters;
- an instantiated CKKS primitive analytical error certificate;
- successful encrypted certification of a public external provider;
- general external-autotuner integration or quality.

They remain `BLOCKED` or `NOT_EVALUATED`. The readiness gate must not promote
them.

## Interpretation

`READY_WITH_SCOPED_LIMITATIONS` means that the evidence package is ready for a
manual research-direction review. It does not mean:

- `paper_claim_allowed=true`;
- permission to start manuscript work;
- a universal CKKS, graph, model, security, or analytical claim;
- that optional extensions have been completed.

The gate binds checkpoint V5, the matched HIT/direct diagnostic, and the live
claim/novelty boundary documents. It is deterministic, non-overwriting, and
keeps `paper_work_prohibited=true` until a separate user direction.
